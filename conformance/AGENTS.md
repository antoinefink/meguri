# conformance/ (MPL-2.0, shared by spec writers and implementers)

- The format, observations, statuses and catalog are `specs/conformance/dsl.md` and `observations.md`; `schema/*.schema.json` mirror them. Change spec, schema, the testkit model (`core/crates/meguri-testkit/src/scenario/`) and, for a new op or kind, the oracle driver together. `schema/protocol.json` is the only interface to oracle workers.
- `goldens/` is written only by `tools/mg oracle record <filter>` (or `tools/mg conformance --live`, which calls it): never edit a golden by hand or bless Meguri output into one. `tools/mg oracle compare <filter>` re-runs the live oracle against the committed goldens.
- A golden goes stale when its scenario's parsed value or the oracle lock changes; comments, key order and layout do not change scenario_sha256. Re-record stale goldens in the same change as the scenario edit. `tools/mg goldens-check` must pass.
- Scenarios are YAML in the JSON-compatible subset, read with the YAML 1.2 core schema (`yes` and `2030-01-15` are strings): no aliases, merge keys, tags or duplicate keys. A scenario's `id` is its path without suffix; one file per id. They define their own note types and CSS and contain no Anki test code or test data text (R1881, R1959).
- The oracle runs Anki's collection library, never its desktop UI: rules that live in Anki's browser, sidebar, previewer or dialogs (column display, sort fallback, saved-search edits, a dialog's remembered defaults) cannot be observed. Scenarios observe stored values and Anki's own reads (`specs/conformance/browser-config-ops.md` B2); Meguri's tests cover those UI-layer rules from the spec tables.
- `scenarios/<area>/area.yaml` (one per area) lists `active` scenarios: T0 fails unless Meguri passes them, T1 for live ones. Mark a scenario active in the change that lands its Meguri adapter.
- A scenario with `handoff` steps is live (dsl.md D9.2): T1 runs its segments on Meguri and the oracle in turn and compares with its golden, which the oracle records running every segment. T0 never runs it. T1 fails on any oracle drift or error, active or not. Anki adds no card to a collection without deck id 1: an oracle segment that adds notes to a collection Meguri made needs Meguri's new collection to hold that deck (`specs/conformance/notetype-ops.md` T10.2). Where template text differs by design (Meguri's stock kinds), observe renders with `render_status` (`render-ops.md` Q4), never text or lengths.
- A scenario with `actors` is live too (`specs/conformance/sync-ops.md`): its clients sync with a server that the oracle worker runs for it, and the parties executor is its only executor. A scenario never names a host, port or credential (R1876). Under a frozen clock, changes and syncs in the same instant look unchanged to the status check: advance the clock before each actor's block (S4.3). A one-way download leaves `mod` equal to the server's, so the next `normal` syncs nothing until a local change. A receiver stamps incoming graves and tags with its own round's `usn`, which `converge` reports: observe those parties with `db_dump` (S12). Keep one top-level `other` member per blob wherever digests are compared.
- An op Anki refuses records `{<op>: {"error": <kind>}}` and the run goes on (D7.3); kinds are the op's closed list in D7.2, added with the driver op. Never encode a refusal another way.
- `oracle.json` is the current oracle pin (`lock_sha256`, and `macos_lock_sha256` for the native lane); it changes only when adopting a bump, with both lock files, every golden and every overlay.
- `goldens-apple/<id>.json` (overlays, `specs/conformance/float-determinism.md` F7) hold the values where the macOS native oracle differs from a golden. Only `tools/mg oracle record --platform apple <filter>` writes them; they go stale with their scenario, their golden's observations or the macOS lock. Only macOS T0 applies them, and goldens-check rejects any entry outside the `fp-libm-boundary` class (F8): a difference outside it is a finding to escalate, never something to edit away.
- `schema/timing.schema.json` is the report both sides of the Meguri-versus-Anki timing write (`tools/mg oracle time`, `meguri-cli timing run`; `specs/conformance/timed-operations.md`). Timings are never goldens: nothing records them under `goldens/` or `goldens-apple/`.
- `deviations.yaml`: one entry per deliberate difference, with its requirement and the test that asserts Meguri's behavior. Nothing else may differ from a golden.
- `catalog/harvest.csv` never names an Anki file or test; the id → test link is `oracle/harvest/links.csv` (spec side). Spec writers regenerate both with `tools/mg harvest-inventory [--supplementary]` and classify their area's rows (`supplementary` rows: main-branch tests, in scope only when the behavior exists at the tag), and re-review rows a re-inventory reopens because the test's source changed; `tools/mg harvest-report` reports coverage and runs the leak and inventory-at-pin checks.
- `recordings/sync/<name>/exchanges.jsonl`: Anki-client exchanges with the sync server, bodies decoded (format: `docker/mitm/record_sync.py`), written only by `tools/mg sync-rig up --record <name>` on the spec side, never edited by hand. A probe of the rig is not a recording: delete it. Neither is a run whose `up` or `status` reported `recorder-unhealthy` or `recorder-stopped`: it misses exchanges.
- `recordings/scenarios/<scenario id>/`: the oracle actors' exchanges of an actor scenario, with `actor` and `step` per exchange (sync-ops.md S9), written only by `tools/mg oracle recordings <filter>`, never by hand. Re-recording an unchanged scenario still changes the `anki-sync` session ids (`s`), note guids and collection-file hashes: re-record only when `recording.json` would change.
- `fixtures/`: inputs made by the oracle maintainer, never by hand, by Meguri or from `local-data/`. Oracle workers read them read-only at `$ORACLE_FIXTURES`, which every tool that starts workers mounts and sets (`tools/mg oracle record|compare`, `conformance --live`); a new one must too.
- `fixtures/storage/*.anki2`: collection files at schemas 10 to 19, made once with the Anki releases and recipes of `specs/storage/schema-upgrade.md` U16 (old releases included) by `oracle/fixtures/storage/make.sh`. Remaking them changes every byte (ids and stamps come from the clock), so every storage golden must be re-recorded with them. A scenario that opens one (`open`, `specs/conformance/storage-ops.md` P1) has no `setup`; its golden is stable only if three recordings agree.
- `fixtures/preservation/kitchen-sink.anki2` is the recipe scenario `preservation/recipe/kitchen-sink` run on the oracle (`specs/conformance/normalized-dump.md` N9) by `oracle/fixtures/preservation/make.sh`. A recipe change re-records the recipe golden, remakes the fixture and re-records every `preservation/` golden in one change; a remake alone changes the guids, which raw dumps show. Anki drops undeclared protobuf fields on save and Meguri keeps them: a scenario that saves a record carrying them compares its rows without those bytes and checks their presence apart, under a deviation (N11.7, Vocab); put new ones only on records no scenario saves again.
- Undo scenarios (`specs/conformance/undo-ops.md` V5): run a `db_exec` that is not a `select` before the first `undo`, `redo` or `undo_status` (the oracle's setup leaves "Add Note" steps), keep `reopen`, `legacy_*`, `blob_decode` and `check_db` out of a step's undo window (they empty Anki's history), and `advance` 1m between note edits that must not merge.
- Writing blobs with `db_exec`: SQLite's `||` yields TEXT and Anki refuses a blob column holding TEXT, so append with `CAST(<column> || X'…' AS BLOB)`. A statement that changes rows Anki caches (note types, decks) needs a fresh read before Anki sees it (`specs/conformance/model-ops.md` L1).
- Rows `db_exec` inserts (a filtered deck, `specs/conformance/deck-ops.md` K13) take a small fixed id below 1,000,000: an id above the clock's instant shifts every id allocated after it (largest + 1, `specs/storage/ids-usn-mtime.md` I2).
- Anki creates the cards of one cloze note in hash order: never observe their real ids (`ids`, `db_dump` keys) when a note has several. Cards an `edit_note` adds have no logical id: read them with `db_exec` (`specs/conformance/note-ops.md` N3).
- Anki gives new fields and templates random ids and writes several top-level `other` members in no set order: pin ids with `legacy_update` before observing them, and keep at most one surviving top-level `other` member where a scenario reads blob bytes.
- Note type scenarios (`specs/conformance/notetype-ops.md`) observe stock kinds only by name and `notetype_structure`, never their blobs (R1959). For the state right after a sync use `UPDATE col SET ls = scm`, then `advance` before the first op: under a frozen clock a schema change in the same millisecond leaves `scm` equal to `ls`.
- Generated scenarios (`scenarios/<area>/corpus/*.json`, and `scenarios/sched/day/matrix/*.json`) come from a seeded `corpora/<name>/generate.py` (`text` for the text area, `templates` for render, `media` for media, `fp-probe` for fp-probe, `sched` for the day matrix): regenerate, never hand-edit, and re-record their goldens in the same change.
- `corpora/fp-probe/inputs.jsonl` and `param-sets.json` come from the same generator run as `scenarios/fp-probe/corpus/`: regenerate them together, then re-record the goldens and the overlays.
- Media scenarios (`specs/conformance/media-ops.md`): `media_files`/`media_outside` names must differ under NFC + `unicase`, or the scenario cannot run on APFS; advance the clock before a `media_outside` step that must be seen (file times are the frozen clock's); trash a file placed from outside only after a `media_pending` has registered it. The Linux oracle's volume is case-sensitive and Meguri's rules are case-insensitive everywhere: a scenario that leaves a mixed-case name in the folder differs from its golden by design and needs a `deviations.yaml` entry (`specs/media/media-files.md` M14). The native macOS oracle's volume is case-insensitive, so `oracle compare --platform apple media` fails by design: media scenarios never get overlays.
- The oracle computes the scheduler day only when asked (`timing`; `answer` and `next_states` without the unbury) and reuses it until its boundary, across offset changes and config writes; Meguri also computes it at open and before answers. Scenarios that read the timing keys, `col.mod` or buried cards follow `specs/sched/day-clock.md` D14.2.
- Tag scenarios (`specs/conformance/tag-ops.md`): never pass `reparent_tags` a source its rules skip together with a moved source while a note uses the skipped one (Anki panics and the worker's backend stays poisoned), and never set a tag's collapsed state to the value it already has (Meguri and Anki differ there by design). Meguri spells a new tag from implicit parents and Anki does not (`specs/tags/tags.md` T3), and Meguri's renamed rows keep their collapsed state and config (T7): a tag added, renamed or expanded under an implicit parent spelled otherwise, or a rename of an expanded or configured row, needs a deviation entry. Insert differently spelled rows with `db_exec` when only the tree is under test.
- Scenario and golden strings carry U+2028, U+0085 and other line-breaking characters raw: split JSON lines on `\n` only, never with Python's `splitlines()`.
