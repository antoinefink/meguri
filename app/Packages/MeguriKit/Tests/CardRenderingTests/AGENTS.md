# CardRenderingTests

- Simulator-enforced case-sensitive access cannot create case variants on a case-insensitive backing volume. Require volume capability metadata before constructing a real case collision; do not change writer APIs or VM volumes to work around it.
- The Xcode Unit plan runs these in the VM. Swift package tests use a borderless host window at (-30000, -30000) that is never ordered in. In the spikes' plain window WebKit runs no `requestAnimationFrame`; `Support/WebTestHarness.swift`'s window overrides `isVisible` and `occlusionState`, so its pages are visible to WebKit and get real animation frames (settle and visible confirmations) while still never on screen. A presented frame, the swap's frame, the keyboard or a relaunch still goes into the app (`MeguriUITests/CardSwapTimingSpikeTests`, `TestHooks/SpikeRoutes.swift`) through `tools/mg perf-ui` in the test VM.
- Offscreen windows cannot prove OS AX hit testing. `CardWebViewBehaviorUITests.testVoiceOverAnswerTargetWithExternalKeyboardOwner` owns real cursor/speech/traversal proof on Mac, iPhone and iPad in the VM; never enable host VoiceOver. Mandatory Mac native replay proof lives in the app-hosted Snapshot VM suite `app/MeguriSnapshotTests/NativeReplayAccessibilityTests.swift`, method `native_generated_replay_controls_are_named_and_identified_in_webkit_hierarchy`; the host package keeps catalog/DOM and mobile native cases. Package fixtures remain offscreen; no host fallback or app activation.
- Suites that share WebKit and this process's memory nest in `WebKitSuites` (`.serialized`): `RenderingSpikes` and `CardRuntimeSuites` (2-minute limit). `swift test` runs every other test target in the same process, in parallel, and the runtime suites measure time.
- `WebTestHarness` builds pages as native will (U67): the document at the origin root (see `Sources/CardRendering/Resources/CardRuntime/AGENTS.md`), `_showQuestion` called by name, identity and presentation through `meguriCard` in the interaction world. iOS and iPadOS pages are the same page with that platform's document and `cb` handler, so they run on the host too.
- On a simulator: `tools/mg unit-sim` (test VM). A package bundle runs hostless there, with no UIApplication and so no window scene (`UIWindow(frame:)` is deprecated since iOS 26): pages get no window, no animation frames and no appearance. The job therefore hosts this bundle in the Debug app (xctestrun rewrite, `MG_UNIT_SIM_HOSTED`); keep window code scene-only. The VM's simulators have no audio route (audio never loads past metadata): audio cases skip when `runsInVirtualMachine()`.
- `withPage(frameClock: true)` counts animation frames in the interaction world with the test's own rAF loop and stamps `#qa` turning visible, every handler post and marks (`presentStamped`): assert frame distances with it, never with the runtime's own signals. A property set on a `webkit.messageHandlers` object is lost when WebKit collects that object (it hands out a fresh one), so the clock keeps its wrapped handlers reachable; do the same for any other wrapper.
- `#expect(try await …)` alone does not make a closure throwing (the macro hides the `try`): write `withPage { harness, page async throws in`.
- Static argument data for `@Test` discovery must be nonisolated and Sendable under this package’s default MainActor isolation. Give complex tuple samples an explicit type; generated discovery runs outside the actor.
- A bare method-name `unit-sim --only` can leave a parameterized Swift Testing suite empty while other suites pass. Check the actual case log; select the full suite when the method signature is uncertain.
- Xcode 27 `#require` overloads are ambiguous for optional Bool results: assign to a typed `Bool?` local first, then require `value == false` when false is required (nil must fail).
- Media is made at run time (`Spikes/Support/SpikeAssets.swift`: silent MP3, noise PNG, system faces rebuilt from their tables; `TestMedia` in `Support/WebTestHarness.swift`: PNG, silent WAV, H.264 MP4, one face). Commit no binary fixture, and never play audible sound on the host. `Fixtures/runtime/` holds the C16 cases that are whole sides (S9, S13, S15, AE15), synthetic only (R1959, R1960).
- Memory checks count the pages' web content processes too (`spikeWebContentFootprint`: pid through WebKit's `_webProcessIdentifier`, SPI, read only in tests and test hooks). S1(f) failed R1853 for them (decision record s1, escalated): their check is a `withKnownIssue` until the plan decides. Old-card retention is checked with a `FinalizationRegistry` in the page, not with footprints. A footprint includes garbage JavaScriptCore has not collected yet, and allocating to force a collection raises it: never do that before a reading.
- Native audio playback requires confirmed real hardware: the VM has no audio route, and loading audio there can block the next video test. Skip audio before creating its page; keep video enabled.
- Before reading finalization counts, request explicit GC through the test-only pool SPI only after all memory readings, then drain bounded event-loop turns; allocation pressure does not guarantee collection.
- `WKWebsiteDataStore(forIdentifier:)` writes under `~/Library/WebKit/`: use a fresh identifier per test and remove it afterwards, also on failure.
- S1 uses `CardPagePair`; S2 uses `MediaSchemeHandler` over `MediaFixture`'s synthetic files. Keep recording/asset/window helpers, never another renderer or range server. The S1 footprint known issue and hardware skips remain evidence limits, not native-component approvals.
