# CardRenderingTests

- These run on the macOS host in a borderless window at (-30000, -30000) that is never ordered in (root AGENTS.md: nothing on Antoine's screen). In the spikes' plain window WebKit runs no `requestAnimationFrame`; `Support/WebTestHarness.swift`'s window overrides `isVisible` and `occlusionState`, so its pages are visible to WebKit and get real animation frames (settle and visible confirmations) while still never on screen. A presented frame, the swap's frame, the keyboard or a relaunch still goes into the app (`MeguriUITests/CardSwapTimingSpikeTests`, `TestHooks/SpikeRoutes.swift`) through `tools/mg perf-ui` in the test VM.
- Suites that share WebKit and this process's memory nest in `WebKitSuites` (`.serialized`): `RenderingSpikes` and `CardRuntimeSuites` (2-minute limit). `swift test` runs every other test target in the same process, in parallel, and the runtime suites measure time.
- `WebTestHarness` builds pages as native will (U67): the document at the origin root (see `Sources/CardRendering/Resources/CardRuntime/AGENTS.md`), `_showQuestion` called by name, identity and presentation through `meguriCard` in the interaction world. iOS and iPadOS pages are the same page with that platform's document and `cb` handler, so they run on the host too; no `tools/mg` job runs this bundle on a simulator yet.
- `#expect(try await …)` alone does not make a closure throwing (the macro hides the `try`): write `withPage { harness, page async throws in`.
- Media is made at run time (`Spikes/Support/SpikeAssets.swift`: silent MP3, noise PNG, H.264 MP4, system faces rebuilt from their tables; `TestMedia` in `Support/WebTestHarness.swift`: PNG, silent WAV, one face). Commit no binary fixture, and never play audible sound on the host. `Fixtures/runtime/` holds the C16 cases that are whole sides (S9, S13, S15, AE15), synthetic only (R1959, R1960).
- Memory checks count the pages' web content processes too (`spikeWebContentFootprint`: pid through WebKit's `_webProcessIdentifier`, SPI, read only in tests and test hooks). S1(f) failed R1853 for them (decision record s1, escalated): their check is a `withKnownIssue` until the plan decides. Old-card retention is checked with a `FinalizationRegistry` in the page, not with footprints. A footprint includes garbage JavaScriptCore has not collected yet, and allocating to force a collection raises it: never do that before a reading.
- `WKWebsiteDataStore(forIdentifier:)` writes under `~/Library/WebKit/`: use a fresh identifier per test and remove it afterwards, also on failure.
- `Spikes/Support/` is U65's throwaway harness (`SpikeMediaHandler`, `SpikePagePair`). When U67's `MediaSchemeHandler` and `CardPagePair` land, point the spike tests at them and delete the support (decision records `docs/design/decisions/s1-*.md`, `s2-*.md`).
