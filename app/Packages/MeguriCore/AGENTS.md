# app/Packages/MeguriCore/

- `Binaries/` and `Sources/MeguriCoreBindings/` are generated and gitignored. Build them with `tools/mg core-xcframework`; `tools/mg swift-test` builds them, then runs `swift test` and fails on any compiler warning (generated bindings included).
- The Xcode scheme pre-action (U7) runs `env -u SDKROOT /bin/bash <repo>/tools/scripts/build-core-xcframework.sh --xcode` with build settings from the app target: it reads `CONFIGURATION` and `PLATFORM_NAME` and adds that platform's slice. The multiplatform app's `SDKROOT=auto` would break the script's xcrun lookups (nm, xcodebuild).
- Every slice is arm64 only. A generic simulator destination also builds x86_64 and fails to link: build with `ARCHS=arm64` (the app sets it).
- CoreBridge imports the bindings with `internal import`: no generated type in a public signature; map to CoreBridge DTOs. Generated names collide with CoreBridge's (`CancelToken`, `CoreEvent`, `JobOutcome`, `CoreBuildInfo`, `ChangeSet`, `OpSource`): write `MeguriCoreBindings.X` in CoreBridge and in tests.
- Every FFI call runs in a lane's `call(.<bridgeCall>) { ... }`, which signposts it in the CoreBridge category. The names are `BridgeCall`s in `Sources/Instrumentation/IntervalNames.swift`, the single interval registry (U12, R1861): add one there with each new export. Never call the bindings directly from the main actor or a plain `Task`.
- New `BridgeCall`s also update the exact registry expectation in `Tests/InstrumentationTests/IntervalNamesTests.swift`.
- `Instrumentation` (registry, `Signposts`, the review loop's `VisibleConfirmation` contract) has no core dependency, so the UI test bundle links it. `IntervalName`/`BridgeCall` have no public initializer: emit only registered names. Only the R1861 intervals are `fieldReported` (MetricKit keeps few custom signposts per app). Tests make unregistered bridge calls from string literals (`Tests/CoreBridgeTests/TestBridgeCalls.swift`).
- Event/progress callbacks only yield into an `AsyncStream`. Clock and disk-capacity callbacks synchronously return host values and never reenter the core. A synchronous call into the core from a callback fails with a Rust debug assertion.
- Generated error enum cases keep Rust's capitalisation (`.Busy(runningOp:)`); other enums are lowerCamel.
- Tests call test-only exports (Rust `test-hooks`) through `import MeguriCoreBindings`, so they compile only against Debug or Profile bindings. The event listener is process-wide: tests that replace it belong in the serialized `EventTests` suite and go through `withRawListener`, which restores `CoreEventStream`.
