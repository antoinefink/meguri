2. Confirmed. Chose the finding's activity-accounting alternative: runtime threads register atomically with owner `jobs`; worker park/unpark hooks track workers, and a guard tracks the DNS blocking closure until it ends, including after cancellation. Idle pool keep-alive waits no longer count busy. A localhost HTTP test exercises the actual resolver without external DNS; a controlled blocking lookup test checks cancellation and reuse. No new composition-root participant is needed.
3. Confirmed. Quick and full checks explicitly name `main`. A test corrupts page 2 of an attached cache, proves the derived check reports damage, and requires a healthy collection quick check.
4. Confirmed. Launch sweeps collection.media under the collection lock. Only reserved regular files at its top level are removed. Media links, media subdirectories and published files survive. A missing media directory is valid.
5. Confirmed. Suspend computes its deadline before acquiring the lane and uses bounded try_lock; resume bounds lane acquisition to five seconds. Open holds the lane only around its initial/final transitions. Concurrent close during Opening/Upgrading refuses promptly. Job starts use nonblocking acquisition, refusing reentrant starts during control instead of deadlocking the writer/participant. Tests cover a slow open, lane contention and reentrant ordinary/continued starts; conventions are recorded in meguri-engine/AGENTS.md.
6. Confirmed. Removed the explicit-sync-only probe and its alternate production branch. The new test-only `meguri-counting` VFS wraps the default VFS at xOpen and is selected with a `vfs=` URI scoped to the test path before open. It forwards the real file and flags and records filename, open flags, sync flags, result and independent monotonic start/completion times for every xSync of that collection and its sidecars. The 20-answer test matches actual WAL filenames/FULL flags and checks each returned commit's one-second bound using only those records. A separate test distinguishes a NORMAL main-file sync from a FULL WAL sync.
7. Confirmed; Apple verification is queued below. Linux timings do not establish F_FULLFSYNC cost.
