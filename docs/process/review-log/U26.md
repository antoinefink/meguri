## First pass

### Round 1 (a028b71)

Five ways the store could give wrong rows or keep the collection busy:
- A batch of commits whose transaction failed was dropped, with the running refresh's deltas. A rebuild from an older snapshot then swapped in without those commits and said Ready. The refresh now keeps its deltas before the transaction begins.
- Suspend answered before the builder let go of its maintenance-reader snapshot. The writer now answers only after every builder sent Done, and a builder sends Done also when it panics.
- Dropping a component's tables by the prefix `<name>__` also matched the live table of a component named `<name>_`. Tables are now dropped only by the owner read from the stored name.
- A panicking apply, build batch or kept delta killed the one derived writer thread. Component code now runs under `catch_unwind` and fails only its own part.
- Readiness events did not carry `cause_seq` (KTD9). The seq of the commit that made a component stale now travels with its refresh.

### Round 2 (cae8328)

`DerivedTx::commit` cleared its open flag before COMMIT. When COMMIT failed (a deferred foreign key), Drop skipped the ROLLBACK and every later BEGIN failed until the file was reopened, so the D6 recovery rebuild could never run. The flag is now cleared only after COMMIT succeeds.

### Round 3 (97e39dc)

The exclusive-phase test was flaky: it waited for Building, which is published before the builder takes its snapshot. The test now holds the builder at its first batch with the mirror's gate, and a builder that ignores the phase still fails it.

## Fix pass

Before the fix pass, 4c716dd added two tests for the integration branch's L8 change (a swap that fails after it changed the file still moves the generation): the old generation's rows are gone and the store rebuilds, and a swap that fails first keeps the store bound with its rows (D9, D10).

### Round 1 (60b4945)

- Ready did not mean fresh: commits reach the store after they are published, so a consumer that reacted to a ChangeSet could read rows without that commit. The stamp now carries `seq`, `DerivedHost::is_current(component, snapshot)` reads it through the consumer's own snapshot, and the writer publishes `DerivedApplied` (change-stream S3).
- A "rebuild" capture during a catch-up was lost, so a sync commit older than the catch-up's `since` was missing. Such a capture now turns the catch-up into a rebuild.
- The 150k rebuild test asserts a wall-clock budget, so it is named `*_at_150k` and nextest runs it alone.

### Round 2 (2da23a5)

`is_current` accepted a derived view that held commits after the consumer's snapshot. SQLite fixes the view of an attached file at the first read of that file, not when the snapshot begins. `is_current` now wants exactly the snapshot's commits (D8), and the engine AGENTS.md says to ask before the first derived read.

### Round 3 (48a2e43)

A refresh could stamp rows newer than its `seq`: a commit releases the commit lock before its observers run, so a rebuild's snapshot could hold a commit the writer had not been sent yet. The builder now waits for the change stream to settle up to its snapshot's seq (`wait_settled`) before it finishes.

### Round 4 (08a2337)

A failed readiness write (`ready` 0 after a failed commit transaction, or an invalidation) was ignored, so stale rows could later pass `is_current` and be stamped clean. Such a failure now unbinds the store, and the next open repairs the rows by D5.2. A replacement that binds an unbound store now empties every component, as D10 asks.

### Round 5 (bac37ff)

A resume that could not write `clean` 0 still answered success, so the file kept `clean` 1 while ops committed, and the next open could take stale rows for fresh. Resume now answers with the error and unbinds the store. A file let go of while it says `clean` 1 is kept until `clean` 0 can be written into it: at a later commit, suspend, resume or close. Every path that lets go of the file goes through `release_file`.
