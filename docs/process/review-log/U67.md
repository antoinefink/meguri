The component uses two persistent opaque full-frame pages, the fixed media
origin and shared store, safe descriptor-relative media opens, streamed bounded
reads, strict range responses, platform bridge admission, live appearance and
same-page question/answer updates. The isolated host transport admits only
matching native identities, acknowledged revisions and bounded current probes.
Template errors retain private UI detail only in bounded memory; exported
technical diagnostics remain sanitized.

Native audio has one actor owner for each player. Logical state changes remain
synchronous; physical operations, leases and descriptor cleanup are serialized.
Preparation and lookahead are bounded and silent. Immutable native delegate
epochs reject stale completions across pause, seek, replacement and close.

Collection media-index/home-deck policy wiring remains with U175. Additional
codecs/video are U69, navigation/recovery U70, and production host/input/layout
producers U176/U180/U181. U67 provides their typed boundaries and tests them with
synthetic callers. Later feature units supply the collection wiring.

## Runtime findings and repairs

- Real native startup and missing-middle queue timing initially exceeded the
  unchanged 50/100 ms budgets. Scheduling at the native device clock plus 5 ms
  met them, but actual play still blocked MainActor for about 160 ms. Moving
  player operations to their actor removed that UI stall without changing the
  observed-position timing criteria or activating idle iOS audio.
- SDK27 requires typed audio deactivation/resumption notifications. The mapper
  preserves manual eligibility and never resumes audio automatically. Real iOS
  builds and policy cases pass without deprecated API suppressions.
- WebKit rejected the original loopback regex. Separate supported expressions
  now block canonical loopback forms; actual rule compilation and iPhone URL
  cases pass. No local-server fallback or weaker rule was introduced.
- S2 navigation gained one owned bounded attempt, cancellation and stale-result
  handling. Actual crash logs then exposed duplicate scheme registration in a
  copied configuration. Clearing its handler did not work on the tested SDK;
  the final fresh configuration shares production store/controller/playback
  policies and registers the measured proxy once. It retains exact range-byte
  checks and the production loader.
- Native footprint grew about 14–15 MB between swaps 100 and 1,000, separately
  from the previously recorded WebContent issue. Suppressing unused burst JSON
  exports did not fix it. Two post-sample malloc/VM snapshots narrowed the
  growth to large malloc-tagged mappings. Avoiding identical explicit native
  appearance setter calls gave one focused pass with 64 KiB
  growth. Runtime JavaScript refresh, paint barriers and explicit nil/unspecified
  override behavior remain intact. The next full suite failed the same native limit by 14,000 KiB. The
  setter guard is useful redundant-work removal, but it did not close the
  footprint failure. Allocation ownership remains under investigation.

Diagnostics preserve the original footprint read, sampling points, rest windows,
GC order, page/DOM/finalizer requirements and thresholds. Region traversal reads
only this process, exports numeric tag aggregates, caps work and marks incomplete
walks explicitly. No addresses, heap contents or paths are exported. No allocation purge or test-limit change was used. Retry policy, quarantine
entries and expected-failure scope stayed unchanged.

A small durable tooling improvement lets `tools/mg ui-test --config Profile`
run selected functional checks in the VM. Debug remains the default. Profile
uses the Performance plan but produces no performance receipt; final performance
acceptance still requires the complete `perf-ui` suite. Six fake-VM checks cover
both configurations, ownership/runtime validation, refusal and isolation.
