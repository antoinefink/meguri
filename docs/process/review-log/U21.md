### A2. KTD4: no prost, and no serde_json `preserve_order` or `float_roundtrip`

- Before: KTD4 and U21's Approach asked for prost-derived message structs, with unknown fields appended on encode, and for serde_json `preserve_order` and `float_roundtrip` across the workspace. U83, U96, U106, U120 and U123 cited those choices.
- Why: `specs/model/protobuf-records.md` P4 writes unknown fields by field number among the known fields, and P5 writes a record whose content did not change back as the bytes it was read with. prost's derived encoder cannot do the first. Untyped JSON values stay their read text (`specs/model/json-numbers.md` N7), so `preserve_order` has nothing to order. std's exact parsers already give what `float_roundtrip` is for. Cargo feature unification would turn either feature on in every crate of a build, meguri-testkit's golden parsing included.
- Now: KTD4 names the hand-written codec and the raw-text JSON layer, and gives the evidence: the property tests with injected unknown fields of every wire type, the conversion-pair tests and the `proto_blobs` fuzz target. U21's Approach, the crate map and the five citing units point to KTD4 as amended. `core/crates/meguri-model/AGENTS.md` points there too.

### A3. U21's test case for a deck `other` with a reserved key

- Before: `{"browser_collapsed":true,"extendNew":10,"x_addon":[1]}` in a deck's `common.other` comes back as identical `other` bytes.
- Why: `extendNew` is reserved for decks. The protobuf field wins, and the key is dropped from `other` (`specs/model/schema11-json.md` S3; the oracle, `model/schema11/deck-other-flatten`). Identical bytes hold only for an `other` with no reserved key and no key the object writes (S3, round trip).
- Now: the case expects S3's result for the example with `extendNew`. For byte identity it uses an `other` without such keys, `{"browser_collapsed":true,"x_addon":[1,{"b":2,"a":1.10}]}`. `tests/schema11_roundtrip.rs` checks both (`deck_other_flattens_into_the_object`, `deck_other_without_reserved_keys_round_trips_byte_identical`).
