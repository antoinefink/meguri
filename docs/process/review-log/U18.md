Two findings, both fixed in 75ec056. The commit does not record their severities.

The job now checks the header write and each row append; a failure records a history-write failure, ends the run in error and counts no rows. 2. `meguri-cli timing run` left an earlier run's `timing.json` or `timing-error.json` in a reused `--out`, so a reader could take a stale report for the current one. The run now removes both before anything else. Two `meguri-cli` timing cases (success then failure, failure then success in one `--out`) fail without the fix.
