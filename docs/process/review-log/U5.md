## Round 1 (fixed in dd5d0ec)

- The pin canary checked only that each pinned version was somewhere in Cargo.lock, and it accepted fsrs's rand 0.10.1 as a workspace requirement. A crate could declare `rand = "0.10"` or `unicase = "=1.4.2"` in its own manifest, or rename rand 0.10.1 in through the workspace, and the canary passed. Now a `via` pin is never a valid workspace requirement, and every path crate in Cargo.lock must resolve each pinned crate it uses to a pin without `via`.
- layering-check applied the row table to every dependency kind, so it rejected the testkit dev-dependencies that U36, U38, U91, U118 and U250 need. Row crates may now use meguri-testkit as a dev-dependency (`[any] row_dev_dependencies` in edges.toml). Normal and build edges to testkit, and any edge to meguri-cli, still fail.

## Round 2 (fixed in 5678d1a)

- edges.toml allowed reqwest only in meguri-sync, but U135 builds the servers' remote-media fetcher on its own reqwest client. reqwest is now allowed in meguri-sync and meguri-servers.
- The core-test canary phase compiled the whole workspace first, so a pin bump that broke a domain crate showed only a compile error and the pin canary never reported the drift (AE82). The canary phase now builds only the packages that have a `canary_*` test target.
- deny.toml left unsound advisories at cargo-deny's default scope (direct dependencies only), so an unsound transitive crate passed core-deny. The scope is now `all`, with a self-test on a fixture advisory database.
