4. P2. The memory check leaves out the WebContent processes. `app/Meguri/TestHooks/CardSwapSpike.swift:445-451` and the host helper in `Spikes/Support` read `phys_footprint` of their own process only, so JS heaps and decoded assets can grow in the WebContent processes while both 1,000-swap checks pass.    - Fix: also measure the pages' WebContent memory, and show that the check catches a deliberately retained page allocation.
   - The fixer's partial work (uncommitted, below) confirmed it. With cards that each keep 64 KB in their page, the current check saw the app process grow 672 KB and passed. With WebContent measured, it catches 49–71 MB of growth.

After 1,000 swaps they stayed 12–13 MB above the warm level, also with both pages' cards cleared. One unpaced run settled back to 46 MB at 4,000 swaps. The cause is not known.
   - So S1(f), "memory stays flat", is not shown for web content on the host harness, and the clean host test with WebContent points fails. The S1 record must not report (f) as passed until this is explained or fixed.
