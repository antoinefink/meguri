## Open after round 1

1. [P1] `user-shape.json` is provisional, not extracted from the real collection (`core/crates/meguri-testkit/profiles/user-shape.json`, `"provenance": "provisional"`). The distributions are assumed, so the passing F3 distribution checks compare the generator with assumed values and do not establish R1804. Fix: a session that the user allows to read `local-data/anki/collection.anki2` runs `meguri-cli profile-extract <collection> --media-dir <its collection.media> --tz <user's IANA zone> --out core/crates/meguri-testkit/profiles/user-shape.json` (the tool reads a temporary copy of the collection and its -wal), commits it with `provenance: extracted` in `Profile::to_json` form, and reports any departure from the plan's constants that `the_user_shape_has_the_planned_constants` checks (9 presets, about 8 reviews per card). Then rerun `tools/mg core-test` for the F3 checks at 10k and 100k. Blocked: no documented role may read `local-data/anki/`, and spec writers may not edit `core/`.
2. [P1] No oracle run has passed on the generated collections. Before integration, `tools/mg fixtures-check` failed every target with `oracle-tree-differs` (unit/U11 changes `oracle/`, and the main worktree's `oracle/` was feat/meguri-v1's), so Check Database validity, the counts, the capped due count and the large-field render were unverified. The cause was the environment. See "Integration" for the run after the fast-forward. The check must run again after item 3 lands, because generator version 3 regenerates every collection.
3. [P1] Generated field lengths exceed the profiled lengths (`core/crates/meguri-testkit/src/generate/notes.rs`). Words fill the whole drawn `field_bytes` length, and the cloze prefix and media references are added on top, but extraction measures whole stored fields. The code follows F4.8 as written, so the fix starts with a spec amendment. Measured by the fixer on a 10k collection (seed 1) against `user-shape.json`, total variation distance of `field_bytes`: 0.107 pooled; 0.36 to 0.47 for fields that carry media references; 0.509 for cloze note type 6, field 1. The "first field at least 4" rule also moves note type 2's 105 empty first fields (of 2,000) out of bucket 0. No test compares field lengths. Fix:
   - Spec writer: in F4.8, make the drawn length the length of the whole stored field, with the cloze prefix and each media reference (and its separating space) inside it; words fill the rest, and when the markup alone reaches the length, the field is the markup; normal fronts stay non-empty (F7). Decide whether "the first field at least 4" stays. In F3, add a field-length check at 10k cards that sampling noise allows (suggested: the pooled histogram within 0.05, plus each note type and field with at least about 1,000 generated notes; note types under 300 notes drift 0.05 to 0.15 from noise alone). In F10.4, generator version 3.
   - Then a fixer implements version 3 and the field-length test.
4. [P3] The spec lags 3ee1b8e: F10.2's manifest table does not list `worst_case_sha256` or say that F10.1's reuse compares it, and F10.1 does not describe the `.<name>.lock` and `.<name>.staging-*` entries beside the output directory. Fix: spec writer, with item 3's amendment.
