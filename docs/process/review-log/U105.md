### Open after round 3

1. [P3] A 2xx after a refused redirect sets `newEndpoint` again. Lens: cleanroom; introduced by 587d780.
   - `core/crates/meguri-sync/src/job.rs:290` clears `new_endpoint` when a redirect is refused, but `followed` stays true. The 2xx arm at `job.rs:275` (`self.followed && self.new_endpoint.is_none()`) sets it again if the caller sends another request on the same `Job` and gets a 2xx.
   - Example: `meta` 308 followed, `meta` 200, `start` 308 refused, then any later 2xx.
   - The doc comments at `job.rs:171-173` and `job.rs:229-230` claim more than the code guarantees. It needs a caller that keeps using a `Job` after T7 stopped it, so U105's flow is not affected.
   - Fix: a `refused: bool` on `Job`, set next to the clear at `job.rs:290` and checked at `job.rs:275`. Or reword both comments to say the guarantee holds because the job stops on a refusal.
