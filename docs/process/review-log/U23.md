## Round 1 (fixer s-20261015T080155Z-b2caa27a; fixed in 5a49b9c)

Four P1 defects in the storage write path. 8bd78fb merged feat/meguri-v1 first.

- `CollectionBuilder` checked that the path was free and then let SQLite create the file. A builder that lost a race opened the winner's file, and its cleanup deleted the winner's collection and sidecars. 5a49b9c claims the path with `O_CREAT | O_EXCL`, refuses a path whose sidecar exists, and on failure removes only the file it created (same device and inode) and sidecars that appeared after the claim.
- The journal recorded the cells the caller passed, not the stored row. A sort field passed as text "123" is stored as INTEGER, so an edit of another field listed `sfld` as changed, and the note digest did not match the committed row. Writes now read the stored row back by key and journal that row, bulk inserts included.
- Journal entries were keyed on exact key bytes, but tags compare with unicase. Renaming Foo to foo and then changing the tag again made two entries, and the second before-image was an intermediate state. Tag keys now index by unicase, through the comparison SQLite uses, and `restore()` matches an image to its key by the key's collation.
- `mark_usn` loaded the before-image of every row before it journalled anything, also with no journal (about 180 MB of heap for 50k notes with 1 KiB fields). It now works one page of keys at a time, journals each page as it reads it (so before-images spill past the threshold), and reads no row images when there is no journal.

New tests in `core/crates/meguri-storage/tests/journal.rs` cover each defect. Each failed before the fix.
