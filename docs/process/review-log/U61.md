### A1. R973: cloze parsing ignores MathJax

- Before: R973 said that cloze parsing ignores `}}` inside `\(…\)` and `\[…\]`, so a cloze around math does not close early. U61's Requirements called this MathJax-aware parsing, and its Approach had the tokenizer handle MathJax spans. A test scenario expected `{{c1::\(a}}b\)}}` not to close inside the math, and the fuzz scenario expected no unbalanced span in any output.
- Why: the pinned oracle (26.09.3) closes a cloze at the first `}}`, inside math or not. The `render/cloze/mathjax` golden shows `{{c1::\(a}}b\)}}` closing after `\(a`, and `{{c2::\(\frac{1}{x^{2}}\)}}` closing inside `{2}}`. On the back, R973's second clause (HTML inside math is stripped, C8) then removes the span's `</span>`: `<span class="cloze" data-ordinal="1">\(ab\)}}`. Only Anki's main branch parses clozes around MathJax (supplementary harvest rows, classified not applicable at the pin). The Goal Capsule makes Anki's observable behavior the reference unless a requirement marks a deliberate deviation. R973 described Anki's behavior and marked no deviation. Adopting it now would change what Meguri renders for these notes, and for clozes it leaves unclosed, which cards Meguri generates (C13). Meguri and Antoine's other Anki clients would then disagree about the same synced note.
- Now: R973 states the oracle's behavior and keeps the HTML strip inside math. U61's Requirements, Approach and MathJax test scenario say the same. The fuzz scenario asks for balanced spans where C12 says they hold: whenever the MathJax strip finds nothing to match. The spec (C8, C12, C13), the code, the unit tests, the fuzz target and the goldens already did this, so none of them changes. If a later oracle bump brings MathJax-aware parsing, the spec, the goldens and R973 change with it.

### A2. R977: duplicate type-in answers stay unless all are identical

- Before: R977 said that `{{type:cloze:}}` collapses identical answers to one and otherwise joins them with ", ". U61's test scenario read this as dropping every duplicate: `{{c1::a}} {{c1::a}} {{c1::b}}` gave `a, b`.
- Why: the oracle collapses the answers only when all of them are identical. Otherwise it joins all of them, duplicates included: the `render/cloze/typing` golden gives `a, a, b` (C10). U64 compares the typed answer with this text. With `a, b`, a learner who types what Anki expects (`a, a, b`) would see a mismatch that Anki does not show.
- Now: R977 says "the one answer when all of them are identical, and otherwise all of them in order, duplicates included". U61's scenario expects `a, a, b`. Spec C10, `cloze/typing.rs` and its test already did this.
