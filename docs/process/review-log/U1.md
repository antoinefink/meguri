# U1 review log

Unit: U1, repository skeleton, toolchain pins, Docker dev image and `tools/mg`.
Review rounds run: 3. Implementation: d0e9c50, 11681ee.

## Round 1 (fixed in 0cdd6f7)

Six ways a run reported less than it should:

- The dev image had no cargo-about: `cargo install` without `--features cli` installs nothing and exits 0. Now installs with the feature, and the image build runs nextest, deny and about.
- Docker jobs kept the caller's stdin, so a `while read` loop over jobs stopped after the first docker job. Runs now read `/dev/null`.
- core-test always passed `--no-tests=pass`, so a filter that matched nothing passed. Only a bare run may match nothing now.
- A job that set pass or warn and then exited non-zero reported success. Now `error` with a `job-exit` failure.
- Failed doctor checks added no failure records. Each now adds one with its check id and repro.
- dev-image reported pass without checking that both image inspections succeeded.

## Round 2 (fixed in 7ea93ff)

- Doctor reported Docker as passing on a stopped daemon (`docker info` prints client JSON with an empty ServerVersion and exits 1), then warned about 0 CPUs. Doctor now needs exit 0 and a non-empty ServerVersion.
- bash ran as PID 1 in the dev container, so SIGTERM was dropped and a killed run's container kept running and holding cargo's target lock. Compose services set `init: true`.
- Only `registry/` and `git/` were shared, so cargo's package-cache lock was per container and two containers could unpack the same crate at once. The whole CARGO_HOME is now one shared volume.

## Round 3 (fixed in 49dddfb)

- Doctor compared Docker memory against whole GiB of MemTotal, so a VM given exactly 16 GB warned forever. It now compares bytes against 90% of the setting.
- core-test passed with zero tests when `core/` had no Cargo.toml, even with a filter. Now fails with `no-tests-matched` when arguments are given.
- An interrupted run left no result.json, and Ctrl-C leaked the docker job's container. tools/mg traps INT, TERM and HUP, stops the job's process tree and container, and writes an `error` result with a `cancelled` failure.

## Open after round 3

- P2 (advisory, non-blocking): a filtered selftest that matches no tests reports pass. `tools/mg.d/selftest.sh`, `mg_tap_report`: when `tools/mg selftest --filter X` matches nothing, Bats exits 0 with TAP plan `1..0`, so `seen` (0) >= `plan` (0) and the status is pass with 0 passed. A typo or a stale repro command for a renamed test passes without checking anything (Codex confirmed with a fixture). Suggested fix: treat plan 0 / total 0 as a failure (`mg_failure no-tests-matched`, status fail), at least when `--filter` is given, with a bats test. This is the selftest counterpart of the core-test bug fixed in rounds 1 and 3. Not fixed at integration.
