## Round 1 (fixed in c1d50d3 and 9f33418)

- `tools/mg xcode-check` ran TestHooksTests on the Mac on every run and took over the cursor and keyboard. The Mac run now needs `MEGURI_ALLOW_MAC_UI=1` (set by `tools/mg mac-ui`); otherwise it is reported as queued.
- xcode-check left two booted simulators behind on every run: it recorded the UDIDs it created inside a command substitution, so the exit trap saw an empty list. Fixed in the script's own shell (superseded in round 4 by the pool lease).
- A Mac Release or AppStore build registered the daily-driver bundle ids with LaunchServices and the widget with PlugInKit, so an ad hoc build copy could take the installed app's widget, URL scheme or documents. Both products are now unregistered and deleted after their checks and at exit, and a check fails if a record remains. Bats tests with stubbed host tools pin the cleanup and the Mac UI gate.
- FixtureInstaller copied a fixture given through a symbolic link as the link itself, so the app's writes reached the committed fixture. It now resolves the path and refuses a directory fixture that contains a link.
- The alert route seam took only a title and a message, so no error-state route could name its buttons. `InitialPresentation.alert` now takes an actions builder; sample/alert shows Try Again and Cancel. The requested identifiers on the alert buttons were not added: SwiftUI drops them on the iOS 27 simulator and on macOS (both checked). Tests find the alert by element type and its buttons by label; app/AGENTS.md records the rule.

## Round 2 (fixed in f2b51f2)

- Launched hidden (`open -g -j`), the Mac app quit within a second on sample/alert: the alert was presented as the window was created, the hidden window closed, and a Window-scene app quits after its last window. On the Mac the alert is now presented after `NSApplication.untilUnhidden()`. xcode-check now launches the Mac Debug app hidden on Home and on every test-hook route and fails if it is gone 3 s later (it failed on sample/alert before the fix); routes are read from their `register(...)` calls and a computed path fails the check. AppVisibilityTests cover the helper without taking focus.

## Round 3 (fixed in afd797b)

- A Mac hook launch without `-MeguriWindowSize` reopened at the previous run's saved frame (`NSWindow Frame main` survives `-ApplePersistenceIgnoreState`), so captures of a route changed layout between runs (R1963). Any hook option now implies the standard 1180x780 window; a launch with no hook option keeps the saved frame. Checked with hidden Mac launches; `testMacWindowSize` covers it and runs only through mac-ui. The fix was applied via Codex (review round 3 relay).

## Round 4 (fixed in 858e3bb)

- xcode-check still created, booted, shut down and deleted throwaway simulators, which the integration branch now forbids (fresh boots and shutdowns put crash dialogs on the user's screen). It now leases an iPhone and an iPad from `tools/scripts/sim-pool.sh` after the Mac builds and releases them at exit; given `--iphone`/`--ipad` devices are used as they are. Bats tests check the lease order, release, a busy pool, and that simctl create, boot, shutdown, erase and delete never run.
