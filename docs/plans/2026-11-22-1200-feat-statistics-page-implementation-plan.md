## 1. What already exists (master, 2026-11-22)

From a read of `core/` and `app/` (no code changed by this plan):

- **Core.** `meguri-stats` holds Card Info only (`card_info/`, `text/`; U92, PR #82). The graph engine is specified (`stats/graphs-*`) and not built: no `stats_columns` component, no graph request, no records. The testkit has a `stats` executor for `card_stats` only (`meguri-testkit/src/exec/stats.rs`); the graph observation (G14, V8, C12) is missing. Built Meguri reads: the activity heatmap (`meguri-engine/src/activity.rs`: AH4's home-deck rule over 371 days, with FFI) and Today's numbers (`studied.rs`, T12, with FFI); H11 needs a new query (G2.1, every year).
- **Derived store.** The store and its host exist (`meguri-storage/src/derived`, `meguri-engine/src/derived_host.rs`) with change-stream application, but no production component is registered (only `tests/derived_lag.rs`), and D4's items added for U98 on 2026-11-17 (`deferred until`, persist, release, `signal()`, `request_refresh()`) are not built.
- **FSRS.** Memory items and per-entry states for one card (Card Info, `sched/fsrs-items` I3 to I5, C6.3) are built; nothing replays every card.
- **App.** `Features/Stats/Stats.swift` and `Features/CardInfo/CardInfo.swift` are one-line placeholders; nothing in `app/` imports Swift Charts yet, so U295 is its first use. `AppSection.sidebar` is `[.home, .browse, .stats, .noteTypes, .settings]` and `CompactTab` holds Decks, Browse, Stats, Settings; the section is not in `availableSections`. HeatmapKit's `ActivityGrid` is built (N24.6's squares and levels) as a trailing window of at most 53 weeks, not year blocks. Browse's shell (U270) has landed; its table (U270a, PR #106) is in review; its search field (U271) is not started.
- **Recent defect class.** Sections opened before a collection existed (first run) failed (PR #111, open: "Note Types and Browse wait for a collection"). Every screen unit below checks first run and no collection explicitly.

## 2. Conventions for every unit

- One implementer, one PR against `master`, opened early and ready for review; its own commits with the trailers of `docs/process/provenance.md` (`Role:`, `Spec:` with the spec ids it implements, `Session:`), the privacy and similarity checks, an independent review.
- Implementers build from the specs named here, never from the round 11 HTML page; layout is N25, then the native build is looked at (`docs/design/workflow.md`: the critic, `tools/mg critic`, and design agreement through `tools/mg gallery`).
- Core integration tests go through each crate's `tests/main.rs`: each unit adds its own test file (`history_states.rs`, `history_knowledge.rs`, `history_parts.rs`, `by_deck.rs`, …) and one `mod` line, so parallel units never share a file. Collection benchmarks live in `core/crates/meguri-testkit/benches/`.
- Verify with the smallest `tools/mg` jobs: core `tools/mg core-test -- <filter>` and `tools/mg core-lint`; benchmarks `tools/mg bench --sizes 150k --bench <target>` (and `bench-mac`); Swift models `tools/mg swift-test --package MeguriKit -- <filter>` (CoreBridge: `--package MeguriCore`); app `tools/mg build-app --platform mac` and `--platform ios-sim`; state snapshots `tools/mg snapshots` (R1970's state coverage for `stats.overview`: empty, typical, overflow, error, loading); screenshots `tools/mg screenshot --route <route>`; UI tests `tools/mg ui-test` (a named class) and `tools/mg mac-ui --suite drive:<script>`; accessibility `tools/mg a11y`; all VM jobs one at a time; UI performance `tools/mg perf-ui --suite StatsPerfTests`; design docs `tools/mg design-docs`.
- **Reaching the hidden section.** U296 adds a `StatsRollout` flag and `app/Meguri/TestHooks/StatsRoutes.swift` (routes `stats`, `stats/deck/<id>`, `stats/chart/<box>`), as Browse and Note Types did, so every screen unit can capture the page before U307 shows it.
- **Required check for every screen unit (U296 to U307):** the first-run state (no collection on the device: the welcome screen, then Statistics reached from its route) and the no-collection states of `stats/statistics-page` S12.1, light and dark, before any other state. A unit that does not show both in its captures is not done.
- **Model and view split.** U294 owns every value the page shows: state, bins, series, figures, streaks, "remembered", the refresh, kept results and the subtitle's text. U295 owns the chart system. Section units own their boxes' views, their S15 elements and identifiers and their S16 strings; they add no model logic (a missing value is a U294 follow-up).
- At most three implementers at once, at most two of them on Swift units, since VM jobs run one at a time.

## 3. Speed (the 150k fixture: 150,000 cards, 1,200,000 review-log rows)

Antoine decided on 2026-11-22 that this page may take longer than others ("it's understood for users that this page can take a bit longer to generate"), as long as it is performant. The figures below are targets to measure, and no unit changes the design to meet one: the tiers, the kept results and the progress shown in each box (`stats/statistics-page` S10) keep the page readable while a read runs. The rows come from `stats/history-reads` H19 (core) and `stats/statistics-page` S19 (app). Every figure is an estimate until the owning unit measures it and records the result in its PR and in the catalog.

## 6. Decisions and defaults (each an assumption the specs make; the owner can change any)

1. **One deck rule.** Every part follows `stats/graphs-common` G2.1 (`did` or `odid` in the subtree), so Show in Browse's `deck:` token finds the same cards, except By Deck, which partitions cards by home deck so its rows add up (H10.1). A filtered deck shows the cards it holds now with their whole history (S12.6).
2. **Days.** Anki's day (B3) folded at 0 for every chart, with dates by AH3's `T0`; weeks start on the system's first weekday, not `firstDayOfWeek` (S3.4).
3. **Anki's three synced display keys** are read, never written; their effects are fixed (always separate suspended and buried, always show overdue).
4. **"Remembered"** is the retention table's rule (V4.1) everywhere on the page, Time of Day included (a Meguri extra beside Anki's `correct`).
5. **Cards Over Time** leaves out suspended cards and deleted cards; buried cards stay in their state (burying and the daily unbury would otherwise rewrite the past twice a day); a card without a log enters on its creation day in its current state; the last day equals Card Counts with buried cards by state, by construction.
6. **Knowledge** replays each card with today's parameters, using only the rows up to each sample (a later review never changes an earlier sample), today included, so it differs from Retrievability's Estimated total knowledge (stored states); the chart's page says why. Each card adds between 0 and 1; "studied" counts the cards with an estimate. A preset's cutoff applies only from its date on.
7. **By Answer** leaves out unrated rows (other clients' `ease` 0); the chart's page says how many.
8. **Windows without a time axis** (Answers, Time of Day, By Deck) are 30, 90, 182 or 365 days or all, not week-aligned; 6M's 182 days is Meguri's.
9. **Streak**: a day not yet studied today does not break the current streak.
10. **Kept results** persist on the device per (collection, deck, period) and are dropped when the collection is replaced.
11. **Activity** ignores the period and shows every year.
12. **Show in Browse for a day** uses Browse's Studied On token, labelled "Forgotten on <date>" for Forgotten.
13. **All's axis** starts at the scope's oldest review month for every chart; Reviews Due's All looks at most 24 months ahead, then one Later bar.
