# core/

- Crate layering is `tools/layering-check/edges.toml`, the KTD2 table as data; change it only when the plan's table changes. `tools/mg core-lint` enforces it for every dependency kind. A new workspace crate needs a place there. tokio is allowed only in meguri-sync and meguri-servers, axum only in servers, reqwest only in sync and servers.
- The one exception: a row crate may dev-depend on meguri-testkit. Use testkit only from `tests/`: testkit depends on that crate, so a `#[cfg(test)]` module in `src/` sees two copies of the crate and its types do not match.
- Only meguri-storage writes SQL against `collection.anki2`. Only meguri-ffi knows UniFFI. Only meguri-engine and meguri-host may name the engine's raw open entry point, `open_raw`; every other crate opens collections through `CoreHost::open`. meguri-engine and meguri-ffi never name meguri-storage's storage-only `CollectionBuilder` (edges.toml `[storage_builder]`).
- Parity crates in `pins.toml` are `=`-pinned in `[workspace.dependencies]` at the oracle lockfile's versions and change only with an oracle re-pin. Implementers never choose their versions: while a pin is `pending`, no crate may depend on that crate. `via` pins (rand 0.10.1 via fsrs; regex-syntax and regex-automata via regex) exist only in `Cargo.lock` and no workspace crate may use them, so a bare `cargo update` breaks the pin canary; update with `cargo update -p <crate>`.
- Time and randomness come only from `meguri_model::clock` and `meguri_model::rng` (R1875). `clippy.toml` rejects the system clock and thread or OS randomness; only a clock module or a bench may `#[allow(clippy::disallowed_methods)]`.
- Test files named `tests/canary_*.rs` run first and alone in `tools/mg core-test`, and a failure there stops the run (AE82 ordering). Keep them fast. That phase builds only the packages holding a canary, so keep the pin canary in layering-check, which depends on no workspace crate: a pin bump that breaks a domain crate then still reports the drift.
- A test with a wall-clock bound runs alone through a `threads-required = "num-test-threads"` override in `.config/nextest.toml`, so a full run's load cannot push it past its bound. Tests that assert a wall-clock budget on the 150k collection are named `*_at_150k`, which one override already matches; any other bounded test needs its own entry.
- Keep domain crates Linux-buildable: Docker runs all Rust tests. Apple-only dependencies go under `cfg(target_vendor = "apple")`.
- SQLite INTEGER boundaries use checked `i64` conversions. The pinned rusqlite has neither `FromSql<u64>` nor `ToSql<u64>`, including optional values and test queries.
- The `test-hooks` (model, engine, sync, ffi) and `ankiweb` (sync, ffi) features are never default.
- Fault points are `meguri_model::faultpoint!("<name>")?`. Whether they fire is meguri-model's `test-hooks` feature, not the calling crate's: a crate's own `test-hooks` must enable `meguri-model/test-hooks`. Names belong to U250's catalog.
- Host builds write `core/target/`; Docker builds use the `cargo-target` volume.
- `tools/mg core-test --canaries` runs only the canary phase: it is the merge gate's canary stage (U19), which stops the gate when it fails.
