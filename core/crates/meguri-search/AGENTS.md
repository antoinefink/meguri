# meguri-search

- Specs: `specs/search/` (grammar, errors, canonical-form, query-model; U81 and U82 add theirs). Messages come only from `errors.md` E7.
- Nothing may recurse on the input's nesting (E6): the query is an arena (`ast.rs`) and every walk (parser, canonical writer, plan, tests' deep cases) uses an explicit stack. A recursive helper or a `Box` tree overflows on `((((…))))`.
- Two position spaces: the lexer's indexes into the normalized, trimmed characters, and the caller's character offsets (`Lexer::input_range`; the only shift is the trimmed lead). Node spans and error ranges are the caller's; the FFI converts them to UTF-16.
- Canonical text is checked only against oracle goldens (`canonical_search` in T0) and the spec's examples, never against Meguri's own output.
- Terms compile in `plan/sql.rs` `compile_term`: U82's in `plan/names.rs`, `state.rs`, `props.rs` and `history.rs`, U81's text terms in `plan/text.rs`. Plan errors follow E4 step 3 in one walk: a statement check returns at once, a pattern error (`sql::is_pattern_error`: `invalid_regex`, pattern too long, expression too large) is kept until every term has passed its statement checks. Compile every expression at plan time with `pattern::compile`; the one exception is `deck:current`, whose expression is built in the statement from the stored name (N3.4), so an oversized name fails there as a database refusal.
- Name terms (decks, presets, note types, templates) match inside the statement through subqueries on those tables, never through ids resolved before it runs, so results always equal N1's rules on the snapshot the statement reads. Mark a term slow only when it calls a function per card or note row.
- `Term::scope` is Q3's table and decides the rows (Q5): a term must read only the tables its scope names.
- `tests/canonical_roundtrip.rs` runs plans through `Plan::build_with` (test-hooks, turned on by the testkit dev-dependency) with a stand-in term compiler, on in-memory tables that hold ids only. The product's term compilers (U81/U82) need a schema-18 collection instead.
- `config.rs` (U83, `specs/browser/config-keys.md`) only reads and computes: an action's planner returns the whole value to write, or `None` for "write nothing", and meguri-engine's `browser_config` applies it through C4. Its `Column` is K3's catalog; U84 extends it rather than keeping a second column list.
- Text terms read the note types the caller passes (`SearchNotetypes`, T15): field names, excluded fields, cloze types and run patterns are fixed at plan time, so the caller reads them on the snapshot the statement runs on, or builds the plan again after a note type change. Name terms (above) stay in the statement.
- Wildcard patterns run on `meguri_like` (a `regex` with `(?si)`, so Unicode folding is the `(?i)` table, C3) in Unicode mode and on SQLite's `LIKE ... ESCAPE '\'` in AsciiCompat mode. A bound parameter that the statement never uses breaks binding: bind only what the SQL holds.
- `-sc:x` is not `NOT (sc:x)` (T9.4): the plan hands a `-` directly before a term that `sql::takes_negation` names to the term (`TermEnv::negated`); `-(sc:x)` stays an ordinary `NOT`.
- `filter_tokens` (U260, `search/filter-tokens` T1-T7) reads only the `NameIndex` it is handed. T7 resolves `deck:`, `tag:` and `note:` terms by name and compares every other item by `Query::canonical_text_of` with a T3 value's built item (`read.rs` `FIXED`, plus the card type, field and J3.2 tag checks): a new fixed value needs its `Value::item` and a place in `FIXED`, or its run text reads back advanced. Text holding syntax runs as its commit (T8's live search). `tests/filter_tokens.rs` runs run texts through the product SQL on a schema-18 copy.
- `BuiltItem::Written` (T3.2) keeps the parsed nodes of its text and marks its top node in the built `Query`; the canonical writer prints the mark's text in place of that node. An advanced token whose canonical text would not read back as the same item (`read.rs` `writes_unchanged`) runs as this item, never as its canonical text.
- Field columns (`browser/fields.rs`, `browser/workspace` V3, V4.2): cells and the sort key read the stored field by exact name. The sort key is one blob per row from `meguri_field_sort_key` whose byte order is V4.2's whole order before the id key; change `sort_key` and the order test (`tests/field_columns.rs`) together. `fields::line` has a fast path that must equal H6 (`text_line_keep_media`).
- Suggestions (U263, `search/filter-tokens` T12): `filter_tokens::suggest` lists rows from the `NameIndex` only and builds a value only for the rows it shows (10,000 tags within one frame): match first, then check tokens and recent keys. `suggest.rs` is D6, used by Browse only when D6.2 finds a key before a colon. Names match by `fold::simple_fold` (the `regex` crate's `(?i)` folding), never by unicase `folded`, which groups field and card type names.
- Filter counts (`filter_tokens/counts.rs`, T12.4): a count must equal the rows its run text's search returns. A deck or tag item is counted by reading its term back (`deck_key`, `tag_literal`) and comparing as the term's expression does; anything else shares a statement of one count column per value built from `plan::compile_predicate`, whose failure leaves `params` as it was (a bound parameter the statement never uses breaks binding). A new term needs its tables in `term_tables`, or the engine's cache keeps a stale count.
