# meguri-model

- Field numbers, wire types, JSON keys, readers and defaults come only from `specs/model/`. A message's `merge_field` and `encode_fields` list the same fields; `encode_fields` writes them in ascending field number (P3). `tests/proto_roundtrip.rs` has its own field tables from P6: change both with the spec.
- Equality of blob content is `BlobMessage::same_content`, P4's equality (floats bit for bit; unknown fields compared per field number, in read order within a number), never `==` on floats. `ProtoBlob::to_bytes` relies on it to write the read bytes back unchanged (P5). Every `Writer` mode sorts unknown fields by number; only `Canonical` interleaves them with known fields.
- Decode depth (P2) is the `Reader`'s `depth` plus the open groups. A nested message's payload is its own `Reader`: nothing open in it may close past its end.
- `other` bytes and unknown fields are opaque outside `schema11/`; nothing else parses or edits them. Only `fsrs_params_6` has a setter (R1486).
- JSON values are read from serde_json raw text (`json.rs`) with std's parsers and written with ryu. Never route a typed value through `serde_json::Value` or `f64`: `0.212f32` widened prints `0.21199999749660492`. Text enters only through `json::parse_value`: it also rejects unpaired surrogate escapes, which serde_json's raw capture lets through, and numbers beyond the 64-bit float range (N10, decided by Anki's fast conversion, not std's exact parser). The one exception is card data: it uses `parse_skipping_range` and checks only the known keys' values with `in_range`, because Anki skips the values of unknown keys. Checks over JSON text are single passes over its tokens (`scan_tokens`): raw capture has no nesting limit, so code that recurses per nesting level overflows the stack on input from a collection.
- The codecs depart from KTD4's wording on purpose: no prost, no serde_json `preserve_order` or `float_roundtrip`. P4 interleaves unknown fields with known ones by field number and P5 writes read bytes back unchanged, so prost's derived encoder is unusable and its decoder would need a second capture scan at every nesting level; P4 equality is bitwise on floats. JSON values stay raw text (N7), so `preserve_order` has nothing to order, and std's exact parsers do what `float_roundtrip` approximates (that feature would also change testkit's parsing). Do not add either back.
- Tests use the model goldens as conversion pairs (`specs/model/schema11-json.md` S14) and never write them.
