# meguri-sync

- `endpoint_guard` (R1876) is the only copy of the sync endpoint rule: the `test-hooks` transport applies it and meguri-testkit re-exports it. It compiles only with `test-hooks`, because a build without `ankiweb` must contain no AnkiWeb name (byte scan, U105/U116); never move it out of that gate. Its test vectors are `tests/endpoint_guard.rs` (`required-features`).
- No AnkiWeb name outside `#[cfg(feature = "ankiweb")]` (or `test-hooks`) code, doc comments included: they reach the library. `tools/mg core-lint` builds the crate without features and scans its object files (`tools/scripts/ankiweb-scan.py`); the `SERVER_CHOICES` const assertion is checked by that build only.
- reqwest stays inside `transport/http.rs`; protocol code (`job.rs`, `login.rs`) goes through the `SyncTransport` seam (KTD14). `http::classify` reads reqwest's error chain with `each_cause`: the TLS handshake's `rustls::Error` sits inside nested `io::Error`s, whose `source()` skips the error they wrap.
- A job draws its session key from the caller's process-wide `RandomSource` (T4). Never seed a source per job: two jobs would share a key.
- The tokio runtime's threads list themselves in the engine's `ThreadRegistry` through the builder's thread hooks (J6), so `runtime::block_on` and `login_blocking` take the registry; the call that starts the runtime picks it until `shut_down`. Only workers call the park hooks: a blocking-pool thread (name lookups) counts as busy until it ends.
- Tests in `tests/transport.rs` that bound time run alone through a `core/.config/nextest.toml` override matching `*times_out` and `a_cancelled_token_*`; name a new bounded test to match, or give it an entry.
- Every test build has `ankiweb` and `test-hooks` (through meguri-testkit), so AnkiWeb rules run under the `aw.test` stand-in (`ankiweb::use_stand_in`) with `JobOptions::pin_host` and `trust_root` pointing at a `sync_stub` TLS server. The stand-in is process-global; nextest's process per test keeps tests apart.
- `rig_*` tests are ignored by default. They read the latest `tools/mg sync-rig` result of the same checkout (`tests/common/mod.rs`, `rig()`) and reach the rig from the dev container through `host.docker.internal`; a test that needs the device clock takes it from the server's `ts` (core-lint refuses `SystemTime::now`): `tools/mg sync-rig up`, then `tools/mg core-test -- --run-ignored only -E 'package(meguri-sync) & test(/^rig_/)'`. `sync-rig up` refuses a branch whose `oracle/` is ahead of the main worktree, so run them in a checkout at the integrated head.
- Every answer decoder reads through `wire::read` (wire-format.md W1.2: the 127-level depth scan before parsing, N9/N10 through `meguri_model::json_text`, envelope members via `Object::get`, which refuses a repeat; `last_wins` only for value maps such as `conf` and `_meta`). Never decode a body with `serde_json::Value` or a derived `Deserialize`: both skip those rules. A new decoder also goes into `core/fuzz/fuzz_targets/sync_json.rs` (W18).
- A decoder that decompresses (the `downloadFiles` zip) bounds its output per entry, in proportion to the body's size (errors.md E6) and absolutely (`MAX_DOWNLOAD_BYTES`), on the declared sizes before it stages anything and again on the bytes while it reads; never `read_to_end` an entry without a `take`. Its files go to the caller's staging directory, never into memory (R1852): only `_meta` is read into a buffer.
- `tests/download_memory.rs` installs a counting global allocator: keep it to one test, so the peak it reads is that test's.
- Decoders return `JobError` (`bad_response`, method set); its `detail` names the place, never body text, and `JobError::from_transport` drops a status's reason (the body's start) and keeps a redirect's `Location` only as an absolute URL without user, password, query or fragment (errors.md E1). `SyncError`'s own text keeps both (transport.md T11), so no `detail` takes a `Status` or `Redirect` error's text whole.
- `offline` needs a typed name-lookup failure: `transport/http.rs` installs `SystemResolver` as reqwest's resolver so `classify` can find `NameLookupFailed` in the error chain. Keep it if the client builder changes.
- `StatusMemory` (meta-status.md M6.1) is the caller's to keep with the open collection; the crate still holds nothing between jobs.
