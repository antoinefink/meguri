# meguri-sync

- `endpoint_guard` (R1876) is the only copy of the sync endpoint rule: the `test-hooks` transport applies it and meguri-testkit re-exports it. It compiles only with `test-hooks`, because a build without `ankiweb` must contain no AnkiWeb name (byte scan, U105/U116); never move it out of that gate. Its test vectors are `tests/endpoint_guard.rs` (`required-features`).
- No AnkiWeb name outside `#[cfg(feature = "ankiweb")]` (or `test-hooks`) code, doc comments included: they reach the library. `tools/mg core-lint` builds the crate without features and scans its object files (`tools/scripts/ankiweb-scan.py`); the `SERVER_CHOICES` const assertion is checked by that build only.
- reqwest stays inside `transport/http.rs`; protocol code (`job.rs`, `login.rs`) goes through the `SyncTransport` seam (KTD14). `http::classify` reads reqwest's error chain with `each_cause`: the TLS handshake's `rustls::Error` sits inside nested `io::Error`s, whose `source()` skips the error they wrap.
- A job draws its session key from the caller's process-wide `RandomSource` (T4). Never seed a source per job: two jobs would share a key.
- The tokio runtime's threads list themselves in the engine's `ThreadRegistry` through the builder's thread hooks (J6), so `runtime::block_on` and `login_blocking` take the registry; the call that starts the runtime picks it until `shut_down`. Only workers call the park hooks: a blocking-pool thread (name lookups) counts as busy until it ends.
- Every test build has `ankiweb` and `test-hooks` (through meguri-testkit), so AnkiWeb rules run under the `aw.test` stand-in (`ankiweb::use_stand_in`) with `JobOptions::pin_host` and `trust_root` pointing at a `sync_stub` TLS server. The stand-in is process-global; nextest's process per test keeps tests apart.
- `rig_*` tests are ignored by default. They read the latest `tools/mg sync-rig` result of the same checkout and reach the rig from the dev container through `host.docker.internal`: `tools/mg sync-rig up`, then `tools/mg core-test -- --run-ignored only -E 'package(meguri-sync) & test(/^rig_/)'`. `sync-rig up` refuses a branch whose `oracle/` is ahead of the main worktree, so run them in a checkout at the integrated head.
