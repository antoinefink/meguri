# meguri-testkit

- The conformance runner implements `specs/conformance/`. `tests/conformance.rs` is T0 (one datatest-stable test per scenario file, `harness = false`); `meguri-cli conformance` is the same library for `tools/mg`.
- An area makes scenarios runnable by adding `src/exec/<area>.rs` and registering its setup sections, ops and observation kinds in `MeguriExecutor::area_registry` (and `AREAS`). Unregistered means `pending`, never `pass`. The new collection a scenario starts from is the setup capability `new_collection` (dsl.md D8; `Scenario::starts_from_new_collection`): the area that makes it registers `Registry::new_collection`, which the executor runs before the setup, and for every Meguri actor when its session is made. Storage registers U28's product bootstrap. An op whose spec splits it into finer capabilities registers them with `Registry::op_part` (`update_notetype.<edit>`). Observation parts use `Registry::observation_part`; stored-card template requests need `template.card`, supplied by U62. A new observation kind whose spec says it never reads the scenario's collection goes in `ObservationRequest::reads_no_collection` (and D8's list), or the scenarios that observe only it turn pending. Adapters take time only from `Session::clock` and randomness from `Session::random`. The session's `Storage` has one Raw or Hosted backend (`engine/host` H4). Engine-owned writes promote it through CoreHost; protocol storage opens remain raw. Never keep both writers, and never nest pooled Query reader leases in one expression.
- `exec/search.rs` fills `SearchContext` from the clock and config; it reads no day yet, so a plan that reads `Today`, `NextDayAt` or a missing `curDeck` is an `unsupported_observation` run error, as for every term of U81 and U82 until it compiles. Fill those values in the change that makes such terms compile (U82), from `sched::day_query_now`.
- The day clock (`exec/sched.rs`: `timing`, `reopen`; `specs/sched/day-clock.md` D14.2) runs the engine's `day_query` on the session's writer with the session's `DayCache`, as the engine's `check_rollover` would. Adapters that change what it computes keep the cache honest: a `db_exec` that does not begin with `select` and every collection open clear it, and a `set_config` or `setup.config` write that changes `rollover` or `creationOffset` runs a day query at once (both go through `storage::write_config`). Fixture `open`, `reopen` and `hand_in` stay raw and run no day query; factory bootstrap follows B11. Promotion runs the automatic D8 check; explicit `timing` keeps the separate compatibility-query cache. `reopen` clears that cache. Timing scenarios query explicitly after reopen (D14.2). Keep the preservation no-churn tests passing through both raw and hosted paths.
- `exec/storage.rs` asserts the schema guard (`storage/schema-18` S6.2) before each `db_exec`, at a hand-out and when a run ends (`Registry::finish`): an op that changes `sqlite_master` fails the run. A scenario that opens fixtures starts with no collection; the executor then refuses every step but `open`.
- Runner tests that stand in for an area build `MeguriExecutor::area_registry` without it: registering an adapter twice panics.
- An op adapter returns `OpResult::Rejected(kind)` for a refusal Anki records (dsl.md D7.3), registered with `op_rejecting` and the op's D7.2 list; `Err(ExecError)` is a run error. The area owning collection files registers `Registry::handoff` (write and open the session directory), which makes live chains runnable (`exec/live.rs`).
- Overlays (`observe/overlay.rs`, float-determinism.md F7-F9) are one implementation for goldens-check (every platform), the macOS runner (`Suite::platform`; tests choose a lane with `on_platform`, never by host) and the fp-probe report (`Suite::oracle_sides`). `diff::compare` applies the `apple_overlay` deviation before every other one; `transforms.rs` leaves it alone. T1, live chains and oracle replays never take overlays.
- `exec/sched.rs` computes `fsrs_next` with meguri-sched's `states::review`, and `meguri-cli fp-probe eval` calls the same functions (F5.5): change them together.
- Read JSON with floats through `observe::parse_json` (exact), never `serde_json::from_str`: serde_json is off by an ULP on 17-digit floats without `float_roundtrip`, and enabling that feature here would change the core's parsing in every test build (feature unification).
- A new op or observation kind changes `scenario/model.rs` (`Step`, `ObservationKind`), the spec and schema, and the oracle driver in one change; f32 values go through `observe::f32_value`.
- An optional model member the schema types without null is `#[serde(default, deserialize_with = "present")]`: a bare `Option` reads an explicit null as missing, so an invalid scenario would load.
- An op whose argument is a mapping reads it through `mapping` or `op_mapping` (a variant's `deserialize_with`): a derived struct alone also reads the list of its values, which the schema forbids.
- Scenario YAML is parsed from granit-parser events with the core-schema rules in `scenario/yaml.rs`, not through serde-saphyr's typeless deserializer (it reads `yes`, `017`, `1_000`, aliases, merge keys and tags differently). Its hash must equal the oracle's `canon.py` byte for byte; `tests/scenario_format.rs` checks it against every committed golden.
- `wallclock.rs` is the only system-clock read, for report timing and budgets.
- Runner tests build temporary conformance trees from copies of committed scenarios and goldens; never write to `conformance/`.
- Actor scenarios (`specs/conformance/sync-ops.md`) run only in `exec/parties.rs`, over one interactive worker session (`begin`/`step`/`end`); T0 lists them `live` or `pending` (`Scenario::needs_of_meguri_actors`) and Meguri's executor refuses them. Meguri plays actors once an area registers `Registry::actor` (the raw dump) and reads its seat from `Session::actor`; `net_fault` and `converge` run on the worker and are never Meguri ops. `tests/parties.rs` drives `tests/support/parties_worker.py` (`python3 -I -B`, in both lanes).
- Every sync endpoint a harness, test or adapter connects to passes `exec::sync_guard::check_endpoint` first (R1876). It re-exports `meguri_sync::endpoint_guard` (feature `test-hooks`), the rule's only copy: change it there. `ANKIWEB_HOST` is the only AnkiWeb host name in test code; build AnkiWeb cases from it, never write the host out (U19's static scan).
- `sync_stub.rs` (specs/sync/transport.md T13) is blocking std sockets and threads, one request per connection: tokio stays out of testkit (edges.toml `restricted.tokio`). It binds 127.0.0.1 only; its proxy mode connects only to routes a test gives it or to socket addresses.
- `src/generate/` is the synthetic collection generator (U11, `specs/fixtures/synthetic-collections.md`). Rows go only through meguri-storage's `CollectionBuilder` in `Raw` scopes as model records; `dump.rs` (raw reads) is its only SQL. Every draw comes from `rng::Rng::stream(seed, family, index)`: a note's rows depend only on the seed and its index, so never draw per-note values from a shared stream. Bump `GENERATOR_VERSION` whenever the same request would give other rows: `tools/mg fixtures` reuses `build/fixtures/` outputs by manifest (a worst case also by `worst_case_sha256`, its definition's digest).
- A field's drawn length is its whole stored length (F4.8, `notes::FieldText`): cloze deletions and media references count inside it and words fill the rest; never append markup after the words are cut. References go only into fields drawn at least the first reference's threshold (25 bytes for an image, 21 for a sound), at a rate taken over those lengths (`reference_rate`), so dropped references do not lower the profile's count. `generate_validity.rs` compares field lengths (F3.1) and references per note (F3.2) with the profile.
- An output is assembled in `.<name>.staging-*` beside its directory and published by a rename; a failed run leaves the old output. `generate` takes no lock: a caller whose runs may overlap on one directory holds `OutputLock` from its cache check to the end (`meguri-cli generate` does). Never take it twice in one process: `flock` on a second descriptor waits for the first.
- Oracle validity (F7) rests on traps that look like details: no answer on the pinned day (deck studied-today counters stay default), buried cards in queue -3 kept by config `lastUnburied` = today (-2 needs a sibling answered today), `revlog.time` capped at 60,000, tags on notes in `unicase` order, `nextPos` = notes + 1. An fsrs refusal is `GenError::Fsrs`, never a fallback value.
- A profile holds only counts and numeric histograms; its only strings are `profile::VOCABULARY` values (R1940, checked by `an_extracted_profile_holds_no_text_names_or_ids`). `profiles/user-shape.json` is in `Profile::to_json` form and `provisional` until a role allowed to read `local-data/` replaces it with `meguri-cli profile-extract` output; implementers never run that on the private collection.
- `profile::measure` is the generator's yardstick: change it only with `measure_counts_a_hand_built_collection`, whose expected values are worked out by hand. Compare a generated collection with `measure_against` (the reference's `span_days`): its own span may end a day earlier and shift every day-histogram edge.
- `tests/generate_validity.rs` checks histories by replaying them through its own copy of the F5.1 table and fsrs; never derive expected card columns from `generate::cards`. The oracle side (F11 T1) is `tools/mg fixtures-check`.
- `src/bench/` is U12's harness. A criterion suite times each operation with `Measurement::run` inside `iter_custom` (never `iter`), installs `PeakAlloc` as its global allocator, opens a `WorkingCopy` of a `bench::fixtures` collection (never the shared one), warms it up before criterion starts, and writes `Suite::write(report::results_dir(..))`. Every routine call is a sample, criterion's warm-up included. pN is the smallest sample with fewer than (100 - N)% above it (`Percentile::rank`), so one 20 ms stall in 100 ops is the p99; HDR's `value_at_quantile` would hide it.
- Memory rows are the process's `phys_footprint` on Apple and resident set in Docker (`bench::memory`), sampled while the suite runs; the allocator peak and `sqlite3_memory_highwater` are breakdowns only. Generating a collection in the bench process inflates its resident set: `tools/mg bench` and `bench-mac` make them first with meguri-cli. `bench-mac` runs the same suites natively (10k to 500k); a suite must build and run on macOS as well as in Docker.
- `benches/icount/` files are gungraun suites: group = area, function = operation (perf result name `<group>.<function>`), id `cards_<size>` for the collection. gungraun clears the environment and counts only the bench function; setup (fixture lookup, copy, warm-up) is free. Add the sizes they open to `MG_BENCH_ICOUNT_FIXTURES` (`tools/mg.d/perf.sh`).
- `src/timing/` is the Meguri side of `specs/conformance/timed-operations.md` (U18): protocol, image, summary, stub, package, report. Timed operations go in meguri-cli's `timing.rs` table and time only the entry point the app's bridge calls (`CoreHost::open` and what follows, once U38 lands), never a storage or engine call the app does not make. A run's copies are plain byte copies, never cloned or synced (T3.2). `Session::package` and `Session::stub` are built once per run, on first use.
- `src/private/` is U15's vault (R1938–R1940). `Vault` opens only `collection.anki2`, its `-wal` and the regular files directly in `collection.media/`, and never lists the profile folder; `tests/private.rs` watches that with inotify, not with the vault's own log. The read-only mount does not stop Anki on the host: the database and its log are one state only together (a checkpoint moves pages into the database, then empties the log), so they are copied as a pair with both stamps taken around the whole pair and retried on any change, never checked file by file (`tests/private.rs` races real checkpoints through `copy_to_observed`). No error, report or summary may carry collection text (deck names, tags, fields, media names): `tools/mg` puts them in results agents read. `redact::Candidates::extract` opens a scratch copy of the database, so the vault's copy stays byte for byte the source. Suite check names are `[a-z0-9-]+` and a check's error text goes only to the private log.
- `src/anonymize/` is the anonymized clone (`specs/fixtures/anonymizer.md`). Its SQL goes through `meguri_storage::raw::PlainDatabase` (the work copy outside the open gate: nothing but A4's changes may be written) and the clone is `VACUUM INTO` it. One walker (`text.rs`) serves the rewrite and V1: V1 walks the source and the clone field with two `Names` impls and compares the events, so a change to the tokenizer or the text rules changes both sides; never give V1 its own copy of a rule. Located media names are opaque atoms to the tokenizer (a space or quote inside a name ends nothing). Every draw comes from the place's stream (`Salt::stream`, A3.2), in the place's own order; a new draw site goes after the existing ones of its place, or every clone changes. Errors, the report and V4's locations carry kinds, counts, row ids and config keys only. `sqlite_stat4` files a WITHOUT ROWID table's key samples under the table's name (`tags`), not an autoindex name: a rule that deletes rows by name needs a test that first finds rows under that name in the source.
- `exec/tags.rs` (tag-ops.md G1-G9) runs meguri-engine's `tags::*_in` and `flags::set_flag_in` in a write scope of `Session::storage`, one scope per op, and records no undo step until U38's engine session; `set_flag` needs a `KeepMtime` scope. Its refusals are checked before the scope opens, so they change nothing.
- `exec/notes.rs` uses U27's note ops and field check; like tags it has no undo adapter before U38. Setup deck ids are captured before steps, so raw deletion/reopen cannot change an add's requested deck identity (note-ops N1). Engine golden tests supply test-only missing adapters; those are never executor capabilities or active scenarios.
- `exec/browser.rs` (browser-config-ops.md B1, B2) writes with meguri-engine's `browser_config::set_value_in` in one `Local` scope per op. `browser_config` reports the column, sort, `savedFilters` and `flagLabels` keys raw (C3 value or B2's default), `sortBackwards` and `browserNoteSortBackwards` included, never through K4, K5 or K7. T0 runs every browser/config scenario but the live chain, `new-collection` on U28 bootstrap; `tests/browser_config_conformance.rs` plays `live-roundtrip` as a Meguri-only chain from the new collection (only T1 runs the oracle's segments).

- U28 owns `exec/decks.rs` and the full new collection in `exec/storage.rs` (`storage/new-collection` B11): no note-type bootstrap stand-in. Setup deck aliases retain their ids, but add_note resolves a live stored human name first (K1, K15). `exec/model.rs` supplies legacy JSON reads/patches and `exec/cards.rs` the raw card observation needed by deck deletions. Undo still needs U38's engine session (undo-ops V6); never register a no-op undo adapter.

- The default executor keeps CoreHost's real or unavailable backup provider. Only explicit `fixture_harness` / `Registry::fixture_backup_witness` uses a counted witness on isolated fixture copies; it never proves backup safety or satisfies U127. `Registry::record_changes` records exact events and pre-delete checks without enabling the witness. Normal runs retain no event trace. U127 must revisit the harness override.
- After a hosted sync replaces the generation, refresh with `Session::engine_collection` before observations (U117); it rebinds the cached reader handle and backup witness.

- New observation kinds also change the CLI capability contract in `core/tools/meguri-cli/tests/cli.rs`. Include that test in focused verification; provider-only tests do not cover this separate consumer.
