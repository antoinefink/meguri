# meguri-storage

- Only this crate issues SQL against `collection.anki2`. Never keep a statement or a read transaction open across FFI calls: an open read transaction stops checkpoints and the `-wal` grows.
- Every connection registers `unicase` first (`conn_init`), with `meguri_text::fold::compare_folded` (the `=2.6.0` pin; another `unicase` reorders the name indexes). The probe registers nothing else; writer and readers then run the initializers.
- The open gate writes nothing before phase 4: the probe and the pre-upgrade copy open with `immutable=1` unless a `-wal` or a non-empty `-journal` lies next to the file (`schema/version.rs`). Never open a file that may be refused read-write, and never set a pragma before the refusals. A hot rollback journal is rolled back on a temporary copy first; the original is rolled back in place only once the copy has passed the refusals.
- Never add a schema object to the collection (R2016). Statement texts are `schema/ddl18.sql` (the normalized tokens of `specs/storage/schema-18.md`, interop facts); step 14's `tags` is the only DDL outside it. Compare `sqlite_master` names case-insensitively: schema-17 files store `FIELDS`, schemas 14 to 16 config's `key`.
- Upgrade steps that rebuild a table drop and recreate it, then rerun the stored text of its foreign indexes and triggers (`upgrade::foreign_dependents`). Never `ALTER TABLE ... RENAME` a collection table: SQLite rewrites every view and trigger that names it to the new name.
- The upgrade runs in one `BEGIN IMMEDIATE` on the writer; the WAL switch happens before it. Fault points: `storage.upgrade.after_copy`, `storage.upgrade.in_transaction`, `storage.conn_init.unicase`.
- Step 14's compact JSON (`legacy_json::compact`) reads numbers with serde_json's own parser on purpose: the spec and goldens want `123456789012345678901` as `1.2345678901234567e20`. serde_json's `float_roundtrip` anywhere in the build would change it.
- `raw` (feature `test-hooks`) is the conformance runner's and the tests' only raw SQL; product code gets typed calls. `raw::PlainDatabase` opens a file outside the open gate with only `unicase` registered, for test tools that must write nothing but their own statements (the anonymizer); never point it at a collection the app or a session has open.
- Tests copy fixtures into temporary directories and never open `conformance/fixtures/` with SQLite. They get `test-hooks` through the dev-dependency on meguri-testkit; fault points are process-global, which nextest's process per test keeps apart.
- Rows are written only through a `WriteScope` (`write_scope.rs`): it compares, stamps per `StampMode` and journals. Product code never writes rows with its own SQL; `raw` is test-only.
- The no-op test is one SQL comparison (`rows::select_compare`: `col IS ?n COLLATE BINARY`), so new values get each column's affinity (`sfld` text stored as INTEGER) before comparing. Key lookups keep the column's collation: a tag differing only in letter case is the same row.
- Template and field rows are never stamped (`ids-usn-mtime` S1); `put_notetype` stamps the `notetypes` row whenever one of them changes, and rewrites changed rows delete-then-insert because of the unique (name, ntid) indexes.
- Config values go through `rows::config::ConfigValue`, never serde_json: exact numbers, integer vs float kept, nesting past 128 reads as invalid. A key whose stored value is the same value (C4) keeps its bytes.
- `CollectionBuilder` must stay out of meguri-engine and meguri-ffi (edges.toml `[storage_builder]`). Its config rows must hold `schedVer` 2, or the open gate refuses the new file as v1.
- Journal entries live in fixed chunks and before-images spill past the threshold: keep per-entry size small, the 150k-note rewrite test (`tests/journal.rs`) measures heap growth. Bulk paths never collect a whole batch of row images; with no journal they read none.
- Journal after-images are the rows as stored, read back by key after the write (`rows::stored`; `RETURNING` costs three times as much), never the cells written. Journal keys and `restore` match keys with the key's collation (`rows::same_key`): a renamed tag is one entry.
- `CollectionBuilder` claims its path with `O_EXCL` and, on failure, removes only the file it created (same inode) and the sidecars that appeared after.
