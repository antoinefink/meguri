# tools/vm/

The macOS test VM that runs every Mac XCUITest suite and Mac app-hosted check (U8b), plus every simulator (U8c) (setup and verification: `docs/process/mac-ui-vm.md`; runner: `tools/mg.d/mac-vm.sh`; helpers shared with scripts outside `tools/mg`: `tools/scripts/mac-vm-lib.sh`).

- Remote topology: M5 alone schedules; T9 on M3 Max hosts the headless guest. Install `remote-wrapper.py` as private `tart` and `vm-ssh` files beside `remote.json` (`host`, absolute kit-root `runtime`); use the default per-user config across worktrees (`docs/process/new-machine.md`). Exact MG `run --no-graphics <name>` detaches remotely; new posture VNC uses the private resident owner, never an M5 tunnel. Missing SSD/wrappers return 255. Never track private configuration.

- VM storage may live in the ignored `.local/meguri-vm/` directory or on an external drive. Never track it. The per-host config remains `~/Library/Application Support/meguri/mac-vm.json` (or `$MEGURI_MAC_VM_CONFIG`), `{"tart": <wrapper>, "ssh": <wrapper>, "vms": [<name> | {"name", "ssh", "tart"}]}`. `ssh` runs its arguments as one shell command in that VM; each VM needs its own wrapper. Mac UI runs take the first free VM. The simulator pool lives in the first VM that can run; a second VM adds capacity for Mac UI runs only. Migration: `docs/process/new-machine.md`.
- Jobs start a stopped VM headless in a session of their own (perl `setsid`), so it outlives the job. Never stop, delete or re-create a VM from a job; changing things inside the VM is allowed (Antoine, 2026-10-15). Never change the host's settings for it.
- Products, fixtures, drive scripts, snapshot baselines and the inventory go to the same absolute path in the VM, by tar over SSH (`xcode-check`'s script copies its own products and `VM_INPUTS`): the tests read the app, fixtures and baselines at their build or source paths (`BuildUnderTest.swift`, `HostedSnapshot.swift`), and `/Users/antoine` in the VM belongs to its user. A path outside the checkout is not this Mac's in the VM: a launch fixture there goes under the run directory, and the launch names that path (`mg_vm_fixture`); only this checkout's directories are ever replaced there. Captures the simulators write there (screenshots, videos, snapshot output) come back to the same path here and are removed there. Do not use tart's shared folders: virtiofs breaks Xcode's symlinks.
- Start tests or touch a simulator in a VM only while holding its lease (a recording of the same checkout lets its jobs in nested). Creating, booting or deleting a pool simulator counts as touching the VM (`sim-pool.sh` acquire and gc, `sim-setup`). A remote run outlives a lost SSH session or a killed job, so the lease holder stops any `xcodebuild test-without-building`, xctest, UI-test runner, hidden-launch helper or Debug app host it finds there (`mvl_stop_tests`): when it takes the VM, right after a lost session (`mg_vm_xcodebuild_test`, `xcode_project_check.sh`) and when a job that started one is cancelled (`MG_MAC_VM_TESTING`, set by `xcode-check` around its devices phase too). A run it cannot stop ends the job's remaining suites (`MG_MAC_VM_LOST`), and the VM gets no new run until a later job stops it.
- The VM's login shell is zsh: build remote commands from single-quoted words (`mvl_q`). `TEST_RUNNER_*` variables do not cross SSH by themselves; `mg_vm_xcodebuild_test` passes them with `env`. A host path is the same path in the VM, but the bats fake (`tests/mac_vm_fake_ssh.sh`) maps every test path in a command: a value that must stay a host path (the pool's caller) travels in a file.
- A VM that cannot be reached is the machine's state, not an error (U19c): no logged-in session over SSH within `MEGURI_MAC_VM_BOOT_SECONDS`, an SSH call that exits 255 or whose command could not start or fork there (`mvl_unreachable`: "exec request failed on channel 0", zsh's "fork failed", bash's "fork: Resource temporarily unavailable"), or fewer than `MEGURI_MAC_VM_MIN_FREE_PROCS` (400) free processes after `mvl_wait_procs`, which `mg_mac_vm_take` runs under the lease, after stopping leftover runs (they hold processes) and before any copy. That part of the job is queued (`mac-vm`, with the reason) and the lease goes back at once; doctor lists the step while it lasts. The cause seen on 2026-10-17: meguri-mac's user may run 2,900 processes (`kern.maxprocperuid`), each booted pool simulator holds about 235, and at the limit sshd refuses sessions and simctl cannot fork. Never raise the limit or change the VM's settings for it from a job.
- `log show` in the VM needs `sudo` to see testmanagerd and WindowServer; take `--start` times from the VM's clock (`mg_app_log_now`). Without `sudo`, call `/usr/bin/log`: the remote shell is zsh, whose builtin `log` shadows it.
- The host cannot record the VM's screen: Mac `drive --record` in the VM samples frames in the test runner. Simulators record with `simctl io recordVideo` in the VM.
- The VM's simulators need the pinned iOS runtime: `add-sim-runtime.sh` copies this Mac's image of it into the VM and adds it there (no download); doctor warns while it is missing. Some SpringBoards ignore appearance changes for good (seen in the VM after first boots and early restarts): after every boot the pool checks one and restarts SpringBoard until it applies them.
- `setup-guest.sh` is the one-time provisioning, run in the VM's Terminal (it asks for the VM account's password); it changes the VM only.
- `tools/mg vm-xcode-stage` maintains only Xcode in the already running dedicated pool VM under its retained lease. It stages the complete actual host selection to `~/Applications/MeguriXcode/Xcode-<version>-<build>.app`, preserves the current bundle and uses no-replace publication. Its narrow `mvl_copy_to` receiver checks the exact transport command but never executes its deletion preamble. Failed/partial run directories and private diagnostics remain private for manual inspection; no recursive cleanup. External/escaping bundle links, changed sources and foreign/partial targets are refused. Activation uses read-only readiness/license checks and guest `sudo -n xcode-select` only; missing consent/admin/first-launch actions stay queued as `mac-vm`. Never rerun provisioning to update Xcode. A staging report proves no SDK execution, signed execution or app acceptance.
- Staging's fixed lease guard `vm-xcode-pending` blocks release and stale-holder reclamation until the original transport/receiver joins and every guest control operation's completion are confirmed. Lost SSH or cancellation during publication/activation retains the guard even after a receiver join. Missing proof retains the lease and private run evidence for root-owned maintenance; never clear the guard based on SSH exit alone. Copy admission reserves more than 40 GiB after payload, per-entry allocation slack and run overhead; extraction is bounded by the verified source entry/byte counts.
- `VMAccessibilitySetupTests` stays enabled in the UI plan so explicit selectors execute it. Without `/tmp/mg-vm-ax-enable` it skips before any setup work; with the marker it requires the hypervisor and `meguri` account before checking/changing AX trust. Integrator removes the marker after setup; never opt in on the host.
- Runner registration refresh and prompt-free trust check require both `/tmp/mg-vm-ax-refresh-runner` and `/tmp/mg-vm-ax-enable`, VM-only as `meguri`; root owns marker creation/removal. Refresh completion is not trust proof: run `testCheckRunnerAccessibilityTrust` alone in a fresh `tools/mg` job/runner with the same frozen runner bundle identifier and executable SHA256 as refresh.
- `duo-fold.sh` owns the persistent VNC session (`sim-posture prepare|status` delegates to it). A fresh session or manual stop may restart only under MG's primary VM lease, with no active guest acquisitions or test jobs; expired/orphan acquisition records are read, never reclaimed. New remote sessions use adjacent `remote.json` and `vnc-hosted.py` in the fixed private kit `vnc-owner-v1`; deploy/preflight before drain, then one stopped-confirmed restart. `build/vmh3` retains M5 control evidence. Legacy connected forwards/local routes stay supported. Lost RPCs query receipts/status, never resend input or infer vacancy; see `docs/process/sim-posture.md`. Only its one VNC connection may reach Tart, because reconnecting crashes Tart. A twice-proven disconnected pre-supervisor canonical `build/vm-fold` routes normal commands to the fixed private sibling `build/vmf2`, reusing the canonical venv and primary scheduler; recheck the untouched orphan under the lease before mutation, and refuse when its evidence becomes live or ambiguous.
- `sim-posture inspect` captures privately; `calibrate|open|closed <leased-udid>` adds exact selected signed Hub/window, live lease and fresh tooltip checks. See `docs/process/sim-posture.md`. Calibration is private bounded data, never executable input. Posture never prepares, reconnects, boots or restarts. Unjoined input retains `sim-posture-pending` scheduler/pool fences; never reclaim them from stale PIDs. Previous-format status/inspection requires linked OS process/socket identity; never adopt or tear it down from PID files. Never publish desktop pixels.
