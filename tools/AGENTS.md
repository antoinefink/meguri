# tools/

- `tools/mg <job>` is the only documented way to build, test and verify. A run writes `build/mg/<job>/<run-id>/result.json` (schema `mg-result.schema.json`, bump `schema_version` on incompatible changes), points `latest` at it (never for `--dry-run`), prints only the result path on stdout, and exits 0 for pass and warn, 1 for fail, 2 for error. Job output goes to stderr and `log.txt`.
- Add a job by adding or extending a family in `mg.d/<family>.sh`: `mg_job <name> <host|docker:<service>> <fn> <description>`, then record results with `mg_status`, `mg_count`, `mg_failure`, `mg_artifact`, `mg_user_step`, `mg_detail`, `mg_message`. Do not echo JSON yourself. Every job must survive `--dry-run`; `tools/mg selftest` dry-runs them all.
- Placement is the R1952 rule. A `docker:<service>` job runs its whole function inside that compose service (`tools/mg __exec`), so write it as plain commands for that container. A `host` job runs on macOS and may call `mg_compose` itself; a container it starts gets `--label meguri.mg.run-id=$MG_RUN_ID`, so a cancelled run removes it. Host placement is also how a job mounts data from outside the checkout (the similarity corpus) or runs git on a worktree: inside a container a worktree's `.git` file points to a host path.
- `<git dir>/meguri-session.json`, written by `tools/mg worktree new`, is a worktree's role; `mg_session_role` reads it. Jobs that need `refs/` or `oracle/` refuse implementer and fixer worktrees. Session records are committed where they are appended (the new branch, or the current branch for `session record`), never left in a working tree. Append and commit only through `mg_session_store`: it holds `<git common dir>/meguri-session.lock` (mkdir) across both, because parallel records in one checkout collide on git's index.lock.
- `.claude/settings.implementer.json` is rendered by jq (`worktree.sh`), never sed: paths may hold `&`, `|` or `\`. A new `@PLACEHOLDER@` must be added there, or `worktree new` refuses the profile. Bash deny rules match the whole command text, and options or wrappers come before a subcommand (`git -C x show`, `env X=1 docker run`): a rule for a command starts with `*` and has `*` before each word it pins (`*git *show *oracle*`). Add sample commands to the matcher test in `tests/provenance.bats`.
- Check a value against a word list with `mg_word_in`, never `case " $list " in *" $x "*)`: a compound value such as `implementer fixer` matches that pattern.
- Path lists from git are NUL-separated (`-z`) end to end: without it git quotes names with non-ASCII, tab or newline characters, and `grep`/`case` on them miss.
- `tools/mg` and `mg.d/` must run under macOS `/bin/bash` 3.2 with BSD tools: no associative arrays, `mapfile` or `${x,,}`; guard empty arrays under `set -u` with `${a[0]+"${a[@]}"}`. Pass job arguments to jq with `--arg` or `mg_json_array`, never `--args` (jq parses `-E`, `-c` and `--` there).
- SIGINT, SIGTERM or SIGHUP cancel a run: `tools/mg` sends SIGTERM to the job's process tree, waits for it, stops and removes a docker run's container itself (compose does not do it reliably) and writes an `error` result with a `cancelled` failure. Jobs run as a background child of `tools/mg`, so under macOS bash 3.2 they inherit an ignored SIGINT they cannot trap: make jobs stop on SIGTERM.
- Agents never perform `user_steps` (R1969). doctor only reads host state; `tests/mg_selftest.bats` stubs host commands and fails on any call outside a read-only allowlist, so extend that allowlist when doctor learns a new read.
- Self-tests: `tools/mg selftest` (bats, in the dev container) and `tools/mg selftest-host` (macOS bash, real doctor, Docker from the host). Both run copies of `tools/` in a throwaway repo and never write to the real `build/mg/`.
