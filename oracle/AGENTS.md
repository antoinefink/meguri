# oracle/ (AGPL-3.0-or-later quarantine)

Only spec writers and oracle maintainers work here. Implementers never read this tree (R1956); they run it through `tools/mg oracle ...` as a black box. Nothing outside `oracle/` imports, copies or ships its code (R1869, R1873).

- Add an area's ops and observations as a module under `driver/ops/` or `driver/observe/` with the `registry` decorators; `worker.py`, `session.py` and `harness.py` stay area-free. Write each vocabulary entry's meaning in `conformance/` (protocol.json now, the U4 specs later), never only here.
- `observe/text.py` (pure text functions) works on one scratch collection per worker process, never the scenario's: whatever a function does there must not change a later output (it removes the media files it writes).
- `observe/template.py` renders new-note cases on its own scratch collection: it saves the request's note type there under its exact name (removing any of that name, stock ones too) and removes it after the request. Never save a case's templates (a save validates them). Template error arguments are free text, so details can fit two messages: the one with more fixed text wins.
- Never put Anki's message text in a response or observation (it is localized, R1887). Errors carry a kind, the step and the exception class name. Where Anki answers only in messages (Check Database), read them through the backend's own translations (`ops/maintenance.py`), never against literal text.
- `check` (`collection_check.py`, `tools/mg oracle check`) runs outside any scenario on a copy of a mounted directory. Anki holds an open collection under an exclusive lock: anything reading the file with `sqlite3` does it while Anki has it closed, with a `unicase` collation registered.
- The TAP runner (`tests/__main__.py`) runs tests one at a time, so `setUpClass` never runs: use `setUp`.
- A refusal that is Anki's behavior (duplicate, invalid input) is an output, not an error: declare its kinds with `@op(name, rejects=(...))` (the op's list in dsl.md D7.2) and raise `errors.Rejected(kind)` only when nothing changed.
- When the driver supports only some forms of a draft op (`export`: the legacy package form, `ops/package.py`), a `scenario_check` fails the other forms with `unsupported_op` before any collection, as for an op it does not have.
- pylib raises JsonError, ProtoError and unmapped backend kinds as the same plain `BackendError`: to reject on one kind, read the kind from the backend error as `ops/model.py`'s `KindProbe` does, never by exception class.
- A Rust panic in Anki reaches Python as pyo3's `PanicException`, a `BaseException` the driver never catches: closing the poisoned backend panics again, the worker exits mid-request and the harness reports `worker_died`. Rust's panic hook prints Anki's `file:line` to stderr (implementer-readable logs), so no self-test triggers one. Known case: `reparent_tags` with a skipped source next to a moved one while a note uses the skipped source (tag-ops.md G5); scenarios avoid it.
- `run` with `steps`/`resume`/`handoff` is one segment of a live chain (dsl.md D9.2): the worker reads and writes the handoff directory at `$ORACLE_HANDOFF` (`tools/mg conformance --live` mounts it at /handoff). A resumed session runs no setup; ops find note types, decks and presets by the scenario's names. Areas that keep state outside the session directory add it to what `Session.hand_off` copies.
- Actor scenarios (`specs/conformance/sync-ops.md`) never hand off. `session.col`, `notetypes`, `decks` and `presets` are the current actor's, so a collection op needs nothing else; declare `scope="global"` for ops that run whatever the current actor. The sync server, fault proxy and endpoints are the `sync` session resource (`ops/sync_server.py`). `converge` excludes exactly S7.3's columns (`sync_client.EXCLUDED_COLUMNS`): when oracle actors do not converge, report it to the spec writer, never exclude more.
- `driver/tests/test_sync.py`'s fault-proxy tests skip without `ORACLE_SYNC_FAULTS`. `tools/mg oracle test` starts `sync-faults` and sets it, so a skip there is a failure.
- Worker and harness stderr reaches tools/mg logs that implementers read. Log exceptions only through `errors.log_exception` (class and driver `file:line`s; no source line, Anki frame or message), never `traceback.print_exc`. For whole tracebacks, start a worker by hand with `ORACLE_FULL_TRACEBACKS=1`; no tools/mg job sets it.
- Protobuf values go through `convert.message` and other f32 values through `numbers.f32_value`, or they print as widened f64 (11.262236595153809 instead of 11.262237).
- Time moves only through `Clock.set`/`advance` (epoch seconds in the libfaketime file, `FAKETIME_FMT=%s`, never the `@` form). Pass the frozen instant explicitly where Anki takes a timestamp argument (`answered_at_millis`). `time.monotonic`/`perf_counter` are real.
- `ANKI_TEST_MODE` turns Anki's fuzz off and shifts its clock: the entrypoint unsets it and the worker refuses to start with it.
- Workers need `/scratch` on tmpfs (the compose service has it). On the container overlay a scenario is ~10x slower.
- `canon.py` defines scenario_sha256 (RFC 8785 of the YAML 1.2 core-schema parse). meguri-testkit's scenario parser must produce the same bytes (its tests compare with every golden); change both together.
- Any driver edit changes `driver_sha256` and the image tag. Goldens go stale only on scenario or lock changes; re-record with `tools/mg oracle record` when an edit changes observations, and check with `tools/mg oracle compare`.
- In a checkout without `oracle/` (an implementer worktree), `tools/mg oracle` builds from the main worktree's `oracle/` as checked out there: a driver change reaches implementers only once the main checkout has it. `test`, `bump` and `lock` refuse there. Any copy of `oracle/` files a job makes under `build/` (outside U2's deny rules) is deleted when the job ends; the self-tests check it.
- Scenario values reach Anki unconverted: reject a wrong JSON type with `invalid_scenario`, never `str()` it (Python's `True`/`1.0`/`None` text is not what a Meguri adapter writes).
- Pins move only through `tools/mg oracle bump <version>` (lock via `tools/mg oracle lock`). Adopting a bump is one separate change: staged `requirements.in`, `requirements.lock`, `conformance/oracle.json` and goldens together, plus a re-inventory (`tools/mg harvest-inventory`, R1882).
- Add-on oracles (another quarantined image): `FROM meguri-oracle:<tag>`, add modules, list them in `ORACLE_EXTRA_MODULES`.
- `macos/` is the native lane (KTD24, `macos/README.md`): the same driver in a host venv on an arm64 Mac, for overlay goldens. A driver change must work on both lanes; `hello` reports `platform` and `time_control` on both. In-process tests such as `test_fsrs_next` and `test_overlay` also run natively (`PYTHONPATH=oracle build/oracle-macos-venv/venv/bin/python -m driver.tests <filter>`); worker tests are container-only. `tools/mg oracle test` runs the native host checks on an arm64 Mac.
- Never add a timed lock, event or queue wait to worker code: on macOS libfaketime leaves `pthread_cond_timedwait` alone, so a deadline taken from the frozen 2030 clock waits until 2030 (`macos/README.md`).
- `observe/fsrs_next.py` keeps one scratch collection per worker, like `observe/text.py`; its presets and decks are cached by (parameter values, `dr`, `max_ivl`) and never change after creation.
- Overlay recording and the `fp-libm-boundary` class live in `overlay.py` (harness only, no anki import). Entries outside the class are recorded and reported, never dropped or edited: escalate them to the spec writer (F7.2, F11).
- `tools/mg oracle test` runs `driver/tests/` in the container on the internal network (the isolation test fails anywhere else) plus `tools/tests/oracle_host_checks.sh`.
- `fixtures/<area>/` makes `conformance/fixtures/<area>/` (`storage/make.sh`: old Anki wheels pinned by hash in linux/amd64 images, 26.09.3 in the oracle image). Remaking changes every byte, so re-record the area's goldens with the new files. SQLite keeps deleted rows in free space: a maker that deletes what Anki created (stock note types) turns on `secure_delete` on Anki's connection first and checks the file bytes (`storage/make.py stock-check`, R1959).
- A scenario whose first step is `open` (never an actor scenario) starts with `session.col` None; outside actor scenarios `run_step` lets only `open` run while it is None (after a refused open). A caller-played actor's `col` is None too.
- `provenance/` holds per-section notes (Anki file + tag 26.09.3) for anything specified from Anki's source.
- `harvest/inventory.py` (run by `tools/mg harvest-inventory`, stdlib only, in the dev container) writes `links.csv` and the conformance catalog. The catalog never names Anki files or tests, and the leak check reports only row, column and kind, since `tools/mg harvest-report` logs reach implementers. links.csv tags are the release (`26.09.3`) or, for `--supplementary` rows from `refs/anki` (main), `main@<sha>`; `check --pin` fails when the release rows are not at the oracle pin. `body_sha256` flags a changed test (row reopened, id kept). A change to the span scanners can change the hash of an unchanged test: land it in its own change with a re-inventory at the current tag from a deleted links.csv and `--supplementary` (without it the supplementary rows are dropped), never with a bump.
